# PXA 0.7.0

本版统一更新系统、SDK、DevKit、桌面模拟器、PXADB 和六种板级固件。
配套商城更新至 0.9.2、轻量商城至 0.1.1，一键配置工具 Agent Kit 更新至 0.4.2。
新构建的应用与资源包默认采用 Container 0.2、DEFLATE 压缩和 4 KiB 解压块。
文件扩展名仍为 `.pxa`，应用版本、Core 2.1 和 AOT ABI
`wamr-pxa-aot-v6-core-1` 不随容器格式改变。

## 安装与启动

- 新容器带签名块索引，先认证索引，再逐块校验、解压并写入目标卷的候选目录。
  安装完成后提交候选目录；支持的串口和商城下载路径不再同时保留完整压缩包与解压副本。
  更新期间仍保留旧版本，直到新版本提交成功，因此应预留新版本展开空间及文件系统余量。
- 已安装应用直接读取展开文件，运行时没有压缩包解压开销。正常启动验证签名清单和
  安装身份，不再扫描全部文件；安装和未完成事务恢复仍执行完整校验。
  若安装后存储介质损坏，正常启动不再保证提前检出所有文件损坏。
- SD 上新建的应用私有存储按使用量分配块，不再预分配约 16 MiB 镜像。
  应用逻辑容量和隔离保持不变；已有私有镜像继续读取，不自动迁移或删除存档。
- DEFLATE 的解压内存随块大小有界，不随安装包总大小增长。默认 4 KiB 块适合
  较小内存设备；16/32 KiB 块可提高部分资源的压缩率，但增加安装时工作内存。
  内存不足时安装返回资源不足并清理候选，不会替换已安装版本。

## PXADB 与兼容性

- 增加二进制帧、CRC、偏移确认及接收缓冲协商，减少 Base64 和逐条命令等待。
  串口、原生 USB 的实际速度取决于硬件通路、目标存储和包内容；USB 转串口仍受 UART 限制。
  传输结束、失败和超时均释放临时状态，客户端按设备能力选择支持的协议。
- 同一局域网内可显式选择临时 HTTP 下载，包签名及传输摘要仍须校验；临时服务
  和 Wi-Fi 省电策略在结束或失败时恢复。此方式不是 USB 高速模式。
- 旧 Container 0.1 的安装兼容由 `PXA_ENABLE_LEGACY_CONTAINER` 控制，默认关闭。
  ESP-IDF 可开启 `CONFIG_PXA_ENABLE_LEGACY_CONTAINER=y`；原生 Host 构建使用
  `-DPXA_ENABLE_LEGACY_CONTAINER=ON`。该开关不影响已经安装的应用和存档。
  默认发行只接受 Container 0.2，PXADB 在上传前拒绝旧包，商城 0.7 目录仅下发新版容器。
  开启兼容的自定义固件可通过 PXADB 安装旧包；旧固件继续使用旧版商城目录。
- 新 SDK 默认生成新版包。确需面向旧固件时，打包脚本可显式设置
  `PXA_CONTAINER_STREAM=0`，或底层容器工具使用 `--legacy`；默认使用旧版 LZ4。
  已发布的历史应用和固定版本工具链保持原内容，不追溯重打包。

## 下载与升级

- [SDK、DevKit、模拟器与主机工具](https://github.com/SmartArduino/pxa-system/releases/tag/v0.7.0)
- [板级固件](https://github.com/SmartArduino/pxa-workspace/releases/tag/v0.7.0)

原生 DevKit 支持 Linux x86_64、glibc 2.39+；Windows/macOS 可使用容器与宿主机
串口工具。首次部署用的 `merged.bin` 会覆盖应用、设置和存档；保留数据升级须核对
实际分区表与对应 `flash-map.json`，布局一致才可只刷应用区。Korvo 和 Mosaico
仍须遵守 [0.6.0 升级说明](release-0.6.0.zh-CN.md) 中的历史分区迁移要求。
保留数据升级后，需通过新版 PXADB 安装配套商城包，让商城按设备能力选择新格式目录；
工厂镜像已包含配套商城。禁止跨板型混刷；交叉构建通过不等同于每种板型都完成实机验证。
