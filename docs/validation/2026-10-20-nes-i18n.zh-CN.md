# PXA NES 图标、系统 i18n 与实机性能分解

正式包 **0.1.22 / release_sequence 25**，系统固件 **0.4.0**，设备 PAI Touch / ESP32-S3，序列号 `a4:cb:8f:d5:d4:f0`。保留原发布者和 `pxa-nes` 身份。最终签名清单、设备状态、内存与截图见[交付状态](nes-i18n-20261020/device/final/state-ready.json)和[哈希清单](nes-i18n-20261020/artifacts.json)。

## 图标和语言

- 新增红白机与手柄图标，保留 SVG 源稿和 192×192 PNG，随签名包交付。
- 使用 PXA i18n：`i18n/messages.yaml` 提供英文源文与语义键，`zh-CN.yaml` / `zh.yaml` 提供中文及父级回退，构建生成 `pxa_app_messages.h`。
- `pxa_i18n_init_from_start_config()` 读取系统语言，`pxa_i18n_handle_event()` 响应系统语言配置事件。菜单、友好游戏名、声音状态、悬浮按键与启动器元数据均国际化；没有应用独立的语言开关或语言配置文件。未知语言回退英文。
- 显示间隔、透明度使用具名 `u32` 占位符，翻译可以调整语序。运行时语言变更只重建一次按键覆盖图，并使两个渲染缓冲失效；保留游戏状态、输入、透明度和手柄隐藏状态。
- 字库包含 YAML 文本需要的 115 个非 ASCII 字形，点阵/表约 4,140 字节，继续使用 Noto Sans CJK SC / SIL OFL。中文不在每个游戏帧重新解析，游戏渲染不查询翻译目录，固定 4 MiB 线性内存保持不变。

## 实测刷新率与耗时

全屏 296×240、声音开启、按键底色 38%、每模拟帧尝试绘图。使用与正式包逐字节相同的 S3 AOT，在独立测试身份下操作，避开正式游戏存档。每工况预热后采集三个完整约 5 秒遥测窗口；LCD 完成探针另包含预热，按其自己的完成帧数和时间计算。

| 实游戏工况 | 模拟 fps | LCD 全帧完成 fps | 最大积压 |
|---|---:|---:|---:|
| 重装机兵起始屋内对话 | 59.99 | 11.16 | 0 帧 |
| 马里奥持续右方向与周期 A 输入 | 50.10 | 6.07 | 1 帧 |

马里奥 ROM 被数据库识别为 PAL，目标为 50Hz；强制 60Hz 会改变游戏速度。两工况 Guest 音频丢采样均为 0。LCD 统计包含相同内容的重复全帧传输，不是面板内部扫描 Hz、独立变化画面的计数或光学测量；提交计数不能代替它。结果仅适用于这些场景，不代表所有游戏、地图或战斗。

| 调用耗时 | 重装机兵 | 马里奥移动 |
|---|---:|---:|
| 生成视频的完整内核调用 / 绘图帧 | 26.16 ms | 29.07 ms |
| 跳过视频输出的内核调用 / 模拟帧 | 9.77 ms | 13.95 ms |
| RGB565 转色、缩放与控件合成 / 绘图帧 | 4.51 ms | 9.70 ms |

耗时来自单调墙钟，可能包含宿主抢占，不能直接当作 CPU 周期或占用率。新增 `NES CORE` 将绘图与不绘图帧分开，和 `NES PERF` 用相同 `wall_us` 配对，避免总平均数掩盖绘图成本。按完成帧数加权的[分项汇总](nes-i18n-20261020/profile-summary.json)、[重装机兵原始窗口](nes-i18n-20261020/device/metal-final/results.json)、[马里奥原始窗口](nes-i18n-20261020/device/mario-final/results.json)保留在报告中。

60fps 的单帧预算是 16.67ms。仅绘图帧的内核调用就已超出预算，加上后续转色/缩放仍更长。跳过视频输出时，CPU、PPU 状态、Mapper、APU 仍需推进，不能把这部分也删掉。根据 draw/skip 差值及 `ppu_renderline()` 的 draw 分支，可以把额外开销主要定位到背景/精灵的视频生成路径；这是分支差分定位，尚不是各 PPU 函数的独占周期采样。

重装机兵静止对话只改写约 22–25 个最终 RGB565 像素，输出脏块优化已在工作；但被选中绘图的 NES 帧仍重新生成源视频，静态画面不能自动省掉 PPU 的背景/精灵绘制。马里奥滚动时，输出变化范围更大，转色和缩放开销也更高。

显示链路还需要整帧旋转、排队、TE 同步与 LCD DMA。当前提交是 GuestMapped 缓冲索引与帧号，没有整帧 Guest→Host 的 IPC 复制；板端仍读写完整帧进行方向转换，不能称为端到端零拷贝。HUD 的旋转/提交数字是不同窗口的整数毫秒均值，会变化，不能相加后当成某个固定的屏幕上限。后续优先优化 PPU 图块/精灵热点，再考虑融合转色、缩放与旋转和降低显示等待；本轮没有把预期收益当成实测提速。

## 验证与范围

- ASan/UBSan 下，系统启动语言、运行中语言事件、`zh-Hans-CN` 父级回退、未知语言英文回退、具名数字和游戏/输入状态保留通过；原声音事件编码测试仍通过。
- 字体解码/裁剪、按键与透明度、默认及实验绘图路径各 6,240 帧与完整 RGB565 参考的差分检查通过。实验图块扫描仍默认关闭。
- 最终签名 AOT 在模拟器分别以 `en-US` / `zh-CN` 启动，验证语言、ROM READY 和首帧；计时字段加入前的相同 UI/目录还完成了声音开关、SDL 手柄隐藏和触屏恢复，见 [UI 检查范围](nes-i18n-20261020/sim-ui-checks.json)。模拟器 SIGTERM 收尾仍有既有退出码 -6，未将自然关闭计为通过。
- 实机通过系统“语言”设置切换 English，再返回中文，观察到 `NES LOCALE en-US` / `zh-CN` 及实际菜单、按键变化。最终恢复中文。
- 实机直接比较声音按钮开启/关闭的可见状态，验证开→关→开。宿主音频内存是汇总值，不能以其是否归零作为单个会话关闭的判断。未进行扬声器听感或声学延迟测量。
- 实机音量条出现时，条外区域与暂停底图像素 **100% 一致**；截图来源为 `composed`，消失后恢复游戏 Surface，见[声音与浮层结果](nes-i18n-20261020/device/audio-overlay/results.json)。原宿主回归和刷写过程见[上轮固件记录](2026-10-20-nes-opt3.zh-CN.md)。
- PAI Touch 的调试适配器不提供 controller 注入，当前没有连接实体手柄；本轮不把注入拒绝或 SDL 测试当作新的实体手柄验收。

最终重装机兵标题在文字显示时刻对齐后，与 FCEUX 相同调色板参考比较，排除 HUD/按键区域后的 RGB565 **逐像素匹配率 100%**，非调色板像素为 0，见[最终颜色记录](nes-i18n-20261020/colors-ready.json)。早先一次采集为 99.23%，439 个差异均为标题白色文字尚未出现，后续帧已完整显示，保留[早期记录](nes-i18n-20261020/colors-initial.json)便于核对。

## 存档恢复与最终安装

收尾核对发现正式 NES 安装项和私有目录缺失，原因未确认；不能以此前刷写时数据分区逐字节相同来宣称之后始终未变。停止清理后，通过同一原签名身份的临时恢复组件，仅补写缺失文件，先在隔离模拟器验证恢复及不覆盖已有文件，再从实机读回。

两个 8 KiB 存档及原空日志文件均与刷写前备份 SHA-256 完全一致；随后更新到正式包再次读回，仍完全一致。恢复组件已被正式 NES 替换，独立测试身份已移除。恢复用的存档内容、整片闪存备份和个人游戏包只放在本地忽略目录，报告仅保留[恢复哈希与范围](nes-i18n-20261020/recovery.json)。

最终保留 PXA 浏览器与 NES，系统音量恢复 40%，语言恢复中文。最终启动时先在马里奥中启用声音，再切换重装机兵，避免为开声音而暂停并写入重装机兵的电池 RAM；交付状态与最终读回记录见报告开头链接。电池 RAM 文件不是任意时刻的状态快照，不能保证恢复到更新前同一暂停画面。

当前仍为 C Guest SDK 前端与 C NES 内核。PXA i18n 同样支持 C，因此无需为国际化改用 C++。C++ 前端可保留 C 内核并走同样的 Surface 路径；改变 SDK 包装语言不会自动消除上面的内核绘图、旋转与传输成本，尚未做 C/C++ 同机 A/B。

最新就绪截图为 `device/final/metal-title-ready.png`。原始备份恢复并逐字节验证的证据保留在 `device/final/state.json`；正常游戏在暂停/后台时可更新电池 RAM，最新文件状态另记在 `state-ready.json`。
