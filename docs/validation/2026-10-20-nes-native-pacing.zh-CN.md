# NES 原生尺寸与动态跳帧验证（2026-10-20）

## 交付

同一签名包 **0.1.27 / release 31** 已安装到 Korvo `/dev/ttyUSB0`
和 DOIT GameKit-1 `/dev/ttyACM1`，两者均为 ESP32-S31、PXADB 2000000 baud。
本轮只更新应用，没有刷写固件。游戏包包含用户提供的 ROM，仅保存在本地，
不随本报告分发。包 SHA256、运行固件 ELF 身份和编译源文件哈希见
[summary.json](nes-native-20261020/summary.json)。

## 改动

- Korvo 使用原生 800×480 Surface，256×240 游戏画面居中、不放大，允许黑边。
  Host 不再做此前的 2 倍 CPU 放大。菜单与按键保持原物理大小，i18n 与密度转换保留。
  GameKit-1 使用 320×240 Surface，游戏区域为 `(32,0,256,240)`。
- 继续注册 GuestMapped 双缓冲，提交缓冲索引和帧 ID；黑边只在缓冲失效时清零。
  Host 到面板仍有转换/复制及传输，不能称为端到端零拷贝。
- 控件按实际按钮包围框及其覆盖图块失效；单个按键反馈不再扫描整条控件带。
- 旧版“积压两帧后最多每 250ms 绘制一次”改为绘制/跳帧耗时估计和积压变化反馈。
  默认最长约 200ms 再次尝试绘制，受内核耗时和缓冲可用性约束。
  保留 CPU/APU 模拟时间债务，不通过丢模拟帧制造满速数据。
- 新增调度日志、声音状态验证、GameKit-1 测量入口和 Mapper 检查，防止切换 ROM 后误标数据。

代价：固定线性内存仍为 4MiB，但最大静态双缓冲扩到 800×480；
Korvo 注册像素由 384,000 增到 1,536,000 字节，Guest 可用堆减少。
ROM 3MiB 只是格式准入上限，实际可加载大小取决于 Mapper RAM 和总内存。
本轮没有修改 NES 内核或调色板。

## 实测结果

下表取最终版本三个连续约 5 秒窗口；声音全程确认 `sound=1`，
四组采样的 `audio_drop` 均为 0。马里奥为 PAL，目标是 50Hz；
重装机兵为 NTSC，目标是 60Hz。

| 设备 | 游戏 | 模拟 fps | 显示完成 fps | 三个窗口的积压帧 |
| --- | --- | ---: | ---: | --- |
| Korvo | 马里奥 PAL | 39.99 | 4.71 | 237 → 290 → 329 |
| Korvo | 重装机兵 NTSC | 60.37 | 12.76 | 15 → 15 → 11 |
| GameKit-1 | 马里奥 PAL | 41.35 | 4.77 | 219 → 271 → 307 |
| GameKit-1 | 重装机兵 NTSC | 59.09 | 4.83 | 33 → 37 → 41 |

**四组均未通过“每窗口接近目标且积压不超过两帧”的完整验收。**
Korvo 重装机兵在消化既有积压，平均略超过 60；不能据此宣称稳定满速。
GameKit-1 重装机兵的积压仍增长。马里奥两块板子都未达到 PAL 50Hz。

Korvo 0.1.24 的上轮数据为马里奥模拟 38.18 / 显示完成 3.69fps，
重装机兵 60.04 / 6.08fps。此次显示完成分别约 4.71 / 12.76fps。
马里奥运动场景随死亡/重生而变，不把这组差异当成严格固定指令流的内核性能提升。
两块板子的重装机兵场景也不同：Korvo 是初始房间对话，GameKit-1 是城镇户外。

各项墙钟耗时（ms）：

| 设备 / 游戏 | 不生成视频的内核帧 | 生成视频的内核帧 | Guest 像素转换与合成 |
| --- | ---: | ---: | ---: |
| Korvo / 马里奥 PAL | 18.6–20.7 | 24.8–27.0 | 4.2–6.8 |
| Korvo / 重装机兵 NTSC | 12.3–12.3 | 17.6–17.8 | 2.7–2.7 |
| GameKit-1 / 马里奥 PAL | 17.6–19.3 | 24.0–25.2 | 3.6–6.2 |
| GameKit-1 / 重装机兵 NTSC | 12.8–12.8 | 19.5–19.6 | 3.1–3.3 |

马里奥仅不绘图的内核帧就接近 20ms，几乎耗尽 PAL 每帧预算。
`scan_us` 混合 6502、PPU、Mapper 和 APU 扫描线工作，不能全部归因于背景/精灵绘图；
这些墙钟耗时还包含任务抢占。四组正式窗口均未出现缓冲获取失败。
后续应优先细分 CPU 总线/Mapper 热点和运行时回调间隙，再测提高每次回调处理预算的收益，
而不是仅降低分辨率或改 C/C++ 语言。

## 色彩、输入及浮层

- GameKit-1 完成输出缓冲的无损 RGB565 截图，与同调色板 FCEUX 标题画面
  **57,344/57,344 像素一致**，非调色板像素为 0：
  [结果](nes-native-20261020/gamekit1-colors.json)、
  [截图](nes-native-20261020/gamekit1-metal-title.png)。
- 桌面产品模拟器的 Korvo 尺寸输出排除控件后，48,526/48,526 像素一致。
  Korvo 本轮实机无损截图因串口分块丢失未取得有效完整帧，不把 JPEG 当作精确色彩证据。
  上轮 Korvo 色彩结果仅作为历史基线。本轮软件对照不等于实体 LCD 光学校准。
- GameKit-1 注入标准手柄方向与 A 键；正式日志为 `keys_alpha=0, keys_auto=1`，
  截图确认悬浮按键隐藏。返回触摸恢复、布局与多缓冲失效由原生测试覆盖；
  本轮不宣称重新验证了每一颗实体 GPIO 按键。
- Korvo 系统音量条出现时底图正常：
  [截图](nes-native-20261020/korvo-volume-visible.jpg)。
- “声音开启且无队列丢样”是软件证据，本轮没有进行麦克风录音或扬声器听感验收。

## 方法和回归

真实模拟 fps = 完成模拟帧数 / 日志窗口墙钟时间。
显示完成 fps = 固件 `PERF START display` 到 `PERF STOP` 的
`completed / window_us`，统计窗口包含预热；截图和文件读取在测量窗口外进行。
这不是 Guest 提交计数，也不是 Korvo 顶部 HUD 的面板扫描频率或光学刷新测量。
显示计数不因间隔记录数组装满而截断。

原生回归通过：6 种画布尺寸、两种缓存模式、三种源对齐、双缓冲及按键变化的
**9,360 帧逐像素对照**，控件混合与命中、i18n、音频权限/队列、菜单原地放大、
调度预算/积压保留/用户绘制间隔/缓冲背压。测试日志保存在本目录。
本轮没有重跑所有历史 Mapper/指令 ROM；内核未变，不能扩展为“所有游戏兼容”。

测试中发现一次串口重连及用户切换游戏，该时段结果被排除。
随后用户确认暂停手动操作，再采集标有 `gamekit1-*-final` 的正式窗口，
并验证各窗口 Mapper 与目标游戏一致。其他候选、标题追赶阶段和错误场景结果保留在
`local/nes-native-20261020`，未作为本报告最终数据。

复测入口（先进入相应游戏，开启声音）：

```sh
python3 local/pxa-apps/nes/tests/device_perf.py \
  --port /dev/ttyACM1 --baud 2000000 --board doit-gamekit-1 \
  --serial 1c:29:04:d0:af:6a --hz 50 --mapper 0 --motion mario \
  --warmup 12 --samples 3 --jpeg --require-audio --output local/nes-retest-mario
```

重装机兵改为 `--hz 60 --mapper 74 --motion none`。本轮源码在
`local/pxa-apps/nes`；包位于 `local/nes-native-20261020/package-final/pxa-nes.pxa`。
