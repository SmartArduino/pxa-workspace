# NES 深入优化：空等、编译内联与分数绘图间隔

已在目标设备更新到 **0.1.32 / release 38**，并核对已安装 AOT 的 SHA256。设备停在游戏库，选中重装机兵；原有存档保持逐字节一致，测试应用已移除，`INPUT CANCEL` 已恢复 GPIO 输入。

| 游戏与窗口 | 原版 LCD 完成 fps | 新版 LCD 完成 fps | 新版模拟 Hz | 最大积压 / PCM 丢样 |
|---|---:|---:|---:|---:|
| 马里奥，右+A 自动输入 | 12.25 | 42.99 | 50.022 / 50 | 0 帧 / 0 |
| 重装机兵，房间对话 | 29.53 | 26.03 | 59.937 / 60 | 1 帧 / 0 |

马里奥该窗口显示更新约为原版的 **3.51 倍**。原版马里奥曾出现 19 帧积压；新版该窗口最大 0 帧。正式身份另做 12 个五秒采样窗口：模拟 49.996 Hz、LCD 完成 44.53 fps、最大积压 0 帧、PCM 丢样 0。移动脚本可能包括死亡、重新开始和演示状态，数据代表所测窗口，不代表每个场景固定达到这个显示帧率。

重装机兵的显示帧率比本轮原版回测低 11.8%，这项差距仍然存在；模拟速度维持 60 Hz。不能把马里奥的提升推广为所有游戏的提升。


本轮在 DOIT GameKit-1（ESP32-S31，MCU `1c:29:04:d0:af:6a`）测试。固件保持上轮的并行显示/PCM版本，ELF SHA256 `4d22ba1b0a7f83867e214ee408806590e72e857605c305c144770a5fbe0a7e97`。本轮修改应用，不改变固件和 ABI；沿用已有分工：Guest 模拟在 CPU1，INDEX8→RGB565 转换按区域使用双核，显示准备、LCD 与 PCM 输出在 CPU0；详见[上轮并行验证](2026-10-21-nes-parallel.zh-CN.md)。

## 慢在哪里

马里奥的 1,200 帧指令计数中，`$8057` 的绝对自跳转占 8,837,996 / 12,984,356 条指令（68.07%）。它等待 NMI，没有寄存器或访存副作用，原来却逐条解释。这个比例属于该 ROM 和该输入序列，不能代表所有游戏。

加速仅批量计入当前 CPU 执行片段内的三周期自跳转，保留末条指令的周期超出量。在读取任何指令字节前先核对当前 RAM/ROM 页映射和读处理器，避免历史 NMI 地址已解除映射时的无效访问；再核对操作数字节。IRQ、DMA、JAM、I/O 轮询及不安全映射均保留普通路径。不识别游戏名称或硬编码游戏地址。最终利用 NMI 打断时已有的 CPU 程序计数器和上一帧实际加速的命中情况选择快速路径；没有逐扫描线探测。只有帧入口探测会漏掉马里奥在帧中才进入的等待，而给普通扫描线添加探测又会带来额外开销，因此使用已有中断点。历史 PC 只决定尝试哪条路径，真正跳过解释前仍验证当前实时状态。

初始优化虽然改善马里奥，却让重装机兵下降。原版可执行文件重新安装到测试身份后恢复约 29.5 fps，排除了单纯设备状态变化。检查 WASM 符号后发现：新增快速扫描线循环增加了调用点，LTO 将原先内联的 `ppu_renderline`、`apu_emulate`、`nes6502_nmi` 提取成独立函数。最终显式保留这些热函数在 WASM 中的内联，并让两套帧函数及每帧一次的选择判断独立编译，避免合并成一个大控制流图；普通 6502 解释器和普通总线访问保持原逻辑。对生成代码的检查只证明编译行为变化，耗时收益仍以实机为准。

绘图间隔由整数改为 Q16 分数预算，避免所需间隔从 2.00 稍升到 2.01 时，60 Hz 游戏立即从 30 降到 20 fps。Surface 无空闲缓冲时跳过画面；CPU/APU 时间债务保留。反馈仅在一秒内的最低积压仍超过两帧时增加，避免把批次入口的短暂高峰误判成持续过载；新增测例区分瞬时峰值与持续积压。持续积压通过减少绘图、执行真实模拟帧偿还。发生实际 Surface 背压后，在预算处于接近两帧一画的窄区间内稳定绘制间隔，避免缓冲归还事件尚未处理时反复请求连续绘图；更快场景自动退出此限制。

## 正确性与范围

- 167,979 个自跳转边界案例对照原解释器，签名 `da136bfe` 一致，覆盖周期、flags、DMA、跨页、处理器副作用、映射修改、中断，以及当前/历史中断地址已解除映射的情况。
- 25 个内核回归案例，包括 16 个 Blargg 指令 ROM；比较参考路径与优化路径。
- 马里奥和重装机兵各 1,200 帧，绘制间隔 1 与 4，逐帧 CPU、RAM、PPU、画面和 PCM 签名相同。
- 重装机兵包含开新游戏、行走、对话的 3,600 帧轨迹，按两种绘制间隔各跑一次，与原版签名相同。
- 跳帧器覆盖 60 秒调度、Surface 背压、手动间隔、持续欠帧和一次 250 ms 停顿。空等与跳帧算法通过 ASan/UBSan。解除映射测例另做反向验证：链接旧版 L CPU 时触发 ASan，修正版通过相同测例。

两款游戏的实机对比测试运行在 `pxa-nes-bench` 独立身份下，不读取或覆盖正式存档。控制器输入通过 PXADB 注入，不等于实际按压机械按键。采样期间不截图、不访问存储；结束采样后才取画面和内存。LCD 帧率使用固件的完成计数，包含预热区间，既不是 Guest 提交次数，也不是光学仪器测得的面板扫描频率。

原始 ROM 分别是 50 Hz PAL 马里奥和 60 Hz NTSC 重装机兵。模拟 Hz 表示游戏时间推进；LCD fps 表示真正完成的显示更新，两者不能混用。没有对所有游戏保证 60 fps，也没有将整套有时序依赖的 CPU、PPU、Mapper 强行并行。


## 实测耗时

| 测试 | 绘制帧的内核耗时 ms | 跳帧的内核耗时 ms | 转换与提交耗时 ms |
|---|---:|---:|---:|
| 原版马里奥 | 19.38–23.66 | 14.22–18.50 | 2.73–2.93 |
| 新版马里奥 | 7.46–15.34 | 2.34–9.61 | 3.21–3.74 |
| 原版重装机兵 | 15.22–15.28 | 10.15–10.19 | 2.69–2.81 |
| 新版重装机兵 | 16.06–16.14 | 10.18–10.24 | 2.79–2.90 |

这些是各五秒窗口的平均值范围。内核耗时包含 CPU、PPU 和 APU，转换与提交是应用侧的计时，不等于 LCD 完成延迟，也不包含所有宿主调度开销。重装机兵的完整绘制工作仍超过每帧 16.67 ms 的预算，当前实现需要跳帧才能保持 60 Hz 模拟；不能仅增加提交频率来获得 60 fps。马里奥的空等优化不能替代其它游戏的 CPU/PPU 优化。


## 颜色、界面与内存

最终包模拟器验证了两款游戏、中文界面、触摸与控制器切换和暂停。重装机兵静态标题的有效 RGB565 像素：模拟器 56,832 / 56,832 一致；实机 57,344 / 57,344 一致。比较对象是 FCEUX 参考图经 RGB565 编码后的像素，不是光学色准测量。画面使用原生 256×240 居中显示，允许两侧黑边。

实机还记录了音量浮层显示与消失后的画面、触摸恢复按键和控制器使按键隐藏的截图。界面与内存证据见 [游戏运行快照](nes-deep-20261021/o-memory.json)、[交付快照](nes-deep-20261021/state-final.json)、[浮层比较](nes-deep-20261021/o-overlay-check.json)。本轮不增加帧缓冲或整帧复制。交付快照的内部空闲堆为 123,655 字节，PSRAM 空闲为 10,679,440 字节，预算统计中的分配失败次数为 0；这些是当时的快照值。
