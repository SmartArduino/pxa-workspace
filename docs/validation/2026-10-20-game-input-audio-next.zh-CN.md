# 游戏输入队列修正与 PCM 除法优化候选

本轮主线修正了手柄事件的覆盖和背压处理，移除了 UI 输入事件的临时堆分配。
音频乘法快速路径完成逐采样测试、离线基准及固件构建，**尚未启用到主线或设备**。
采样资源、声部批次和 OPL 的新 ABI/SDK 仍未实现，不将这轮工作称为原引擎混音迁移。
SDK 提交为 `a067126`（UI 事件修正）及 `422c982`（音频采样率覆盖测试）。

## 手柄与事件开销

ESP 原来用 `COALESCIBLE` 提交完整手柄状态。原生游戏在一次协作检查点中可以先处理
多条 Host 命令，再读取 Guest 邮箱，因此后来的松开状态能够覆盖尚未读取的按下状态。
这条覆盖路径可以从队列代码及测试确认；它是否完全解释上一轮真机的短按、后退失败，
仍待新固件复测。

- UI 服务统一把数字手柄状态规范为 `RELIABLE`，同时清除 `COALESCIBLE`。
  旧 Host 传入可覆盖标志也不能丢掉按下/松开次序；原有 wire 布局和 Guest 解析器不变。
- ESP 在移除 Host 队首命令之前尝试投递。Core 返回 `BUSY` / `RESOURCE_LIMIT` 时，
  命令留在队首，等 Guest 消费后重试。回调模式和原生主循环均处理背压。
  失效的应用实例和不订阅手柄的目标仍可丢弃对应事件。
- 所有 UI 输入事件用 24 字节局部头部及借用的值片段，直接复制到原有 Core 事件池；
  省去临时申请、释放及一次值复制。返回后不会保留调用方指针。
- 没有新任务、重试队列或常驻缓冲；Core 邮箱和任务栈预留不变。
  这里不把局部栈空间或尚未测量的整机堆变化描述为零成本。

测试在禁止 UI 临时分配的条件下填满真实 Core 邮箱，交替提交方向按下/松开，
确认队列满时此前的事件不变，腾出一个槽后可重试，整个序列按原时间戳读取。
重试提交后立即覆盖输入内存，读取结果仍正确。该测试没有用等待时间掩盖覆盖问题。

## 音频候选

单 PCM 快速路径原来在每个输出采样计算一次整数除法。候选实现每块计算
`r = floor(UINT32_MAX / output_rate)`，对 32 位分子 `n` 使用
`q = high32(n * r)`，再按 `n - q * output_rate >= output_rate` 修正一次。
这个下界估计最多相差 1，保持原整数截断；负的插值差值仍按幅度计算再恢复符号。
多声部、EQ 和合成音保留原通用路径。

固定 workspace 仍为 **24,144 字节**。倒数是块内局部变量，没有新表或缓存。
RISC-V 构建反汇编确认候选热循环使用 `MULHU`；通用路径仍含除法，未宣称整个混音器没有除法。

正确性测试覆盖：

- 全部 8,000–48,000 Hz 输出采样率，共 40,001 个分母，满幅正负跳变及不规则消费块；
- 8,001、11,027、47,999 Hz 等非标准源采样率与已有常见采样率；
- 独立的原版有符号 64 位除法参考、快速/通用路径一致性、增益和削波；
- 多包预提交、输入复用、队列背压、输出拒绝回滚与暂停/关闭生命周期。

本机 x86_64 微基准，`-O2`、每轮 20,000 包、交替顺序各 5 轮，混音耗时中位数：

| 双声道源 → 48 kHz 单声道 | 原实现 ns/包 | 候选 ns/包 |
| --- | ---: | ---: |
| 11,025 Hz | 51,327 | 39,933 |
| 22,050 Hz | 51,659 | 38,220 |
| 48,000 Hz | 13,956 | 13,403 |

全部 30 次的输出长度和 checksum 一致。前两组本机混音耗时下降约 22% / 26%；
同采样率不经过新插值路径，第三组差异不能归因于此次算术改动。
这是存在其他进程负载的本机墙钟数据，不能换算为 ESP 周期、设备 FPS 或音频欠载率。

候选保存为 [补丁](game-input-audio-next-20261020/audio-reciprocal.patch)，未应用到主线
`audio_mixer.c`。没有为了离线数字直接替换已在设备验证的实现。
