# GameKit 远程手柄保序与测试时钟修正

本轮修复了远程控制器在板级轮询前覆盖短按的确定性问题，并完成原生测试、
ESP32-S31 固件构建和内存对比。**尚未刷入设备，不能据此宣称实机短按、
上下移动或 FPS 已通过。** Audio 0.11 的设备对照也仍待完成。

目标设备 `1c:29:04:d0:af:5e` 的只读检查仍显示 NES 0.1.23 正在运行。
当前刷机、停止应用、安装游戏操作均未执行。是否允许中断这项测试的确认
仍待答复，其他设备也没有被用来替代同设备对照。

## 问题与修正

之前 `inject_controller` 将整个远程控制器状态写入单个 atomic，屏幕任务
在 `ReportController` 中读取。如果按下和松开发生在两次轮询之间，即使两条
PXADB 命令均返回 processed，屏幕任务也只能看到松开。此前 Host 队列和
Core mailbox 的保序修正位于这一层之后，无法恢复已被覆盖的边沿。

现在使用 8 项固定队列：

- 不同状态按序排队；相同状态的保活不占额外空间。
- 每次轮询最多提交一个队首，Host 接受后才移除；繁忙时保留重试。
- Host 调用在临界区外执行。提交期间发生取消或接管时，generation 检查
  防止旧提交错误地移除新队列中的状态。
- 实体按键接管、取消和超时清除远程待处理状态；已经提交给 Host 的事件
  仍可能完成，下一次上报恢复当前来源。
- 满队列拒绝新的不同状态；PXADB 沿用已有的失败取消行为，不能把这种拒绝
  当作一次成功的游戏操作。

未增加任务、堆分配或每帧日志。空闲保活仍为 50 ms，原物理按键去抖逻辑
保持原样。此次修复也不能捕获两次 GPIO 采样之间发生的实体短按；Guest
收到按下和松开后，游戏是否在下一帧前消费它们，仍须单独验证。

## 时钟边界

检查历史串口记录发现，framed LOG 使用 `esp_log_timestamp()`，输入 ACK
使用 `esp_timer_get_time()`。当前本地 IDF 的日志时钟包含自己的启动基值和
FreeRTOS tick，不能将 ACK 的 `device_us / 1000` 直接作为日志时间边界。

输入 ACK 新增可选 `log_ms` 字段，原字段保持兼容。主循环测试要求此字段，
按同一日志时钟排除旧记录，并处理 32 位回绕。同毫秒记录不作为后续进展
的证据；旧固件缺少字段时直接报告不满足测试条件。

测试工具也改为拒绝任意正在运行的应用，避免因只检查 probe 自身而中断
另一项测试。设备身份、占用状态或时钟检查失败时，不执行交互输入、
停止应用或 HOME 清理。完整接口说明见
[输入时序](../pxadb-input-timing.md)。

`processed` 和 `INPUT SYNC` 都不代表游戏已经响应。旧控制实验中的截图、
Guest 日志和实际坐标仍需分别审查；不能以 ACK 成功或悬浮按钮隐藏代替
上下移动成功。这次没有重新将旧实验标为通过，也没有新增 FPS 数字。

## 验证与内存

通过 ASan/UBSan 验证固定队列，以及从实际源码提取的板级上报方法和 ACK
编码函数。涵盖短按两边沿在轮询前到达、Host 连续繁忙、相同保活、队满、
重入取消、断连和 tick 回绕；参考队列模型运行 200,000 次操作。

主循环工具 10 项单元测试通过，覆盖其他应用占用时不发送修改命令、旧固件
时钟缺失、不同钟源偏移、历史重放及回绕。固件链接、codec 内存审计和
分区容量检查通过。
