# GameKit 游戏 15fps 目标的设备验证记录

2026-10-20 更正：下文历史“完整音频”或“默认音频开启”只描述当时的开关设置，
不能作为原音频质量通过。审计确认当前公共桥接与 ESP 后端固定 16kHz 单声道，
C&C 源混音也改成了 16kHz，低于上游默认 22.05kHz 立体声。
历史 FPS 样本保留，完整音频目标仍未通过；见[后续真机与音频审计](game-render-followup-20261020/README.md)。

本轮最低目标为实际关卡 15fps，期望进一步接近 30fps。验收设备为 GameKit /
ESP32-S31、320MHz、16MiB PSRAM、320×240 显示。使用 RISC-V32 ILP32F AOT；
ESP32-S3 的 Xtensa 产物不能用于这台设备。桌面协议宿主的速度不作为真机 FPS。

Duke3D 0.1.20保留384KiB ROM缓存，使用128/16KiB引擎/回调栈及16KiB续体。
实测栈水位为73,456/424字节、续体720字节，无回调超时，结束后确认OpenLara前台

不是额外相加的节省。缓存索引与栈配置提交为`8324e33`。同时存在固件差异，不能
把帧率变化单独归因于索引。当前公开0.1.22采用同一配置；一次锁屏覆盖、无游戏帧
的测试被拒绝计入，重新解锁后才获得上述有效数据。

## 已在设备验证的固件修改

运行线程的原生栈由12KiB扩大到32KiB，解决 Quake 在原生 AOT 调用链上的栈溢出。
这与 WAMR 操作数栈、Guest 链接器 C 栈及 Asyncify 续体缓冲相互独立。

启用 UART ISR 内部 RAM 执行后，2MiB 内部 Flash 文件以2Mbaud、1024字节分块
完整上传，SHA-256一致，没有重传。此前 Flash 缓存关闭期间会丢失上传命令。
启用 FAT 只读文件快速定位，每文件使用64个32位条目；`READ_AT` 的定位和恢复
不必重复遍历长簇链。未更改分区表或格式化存储。

FW25 增加 WAMR 映射申请失败的大小、空闲量及最大连续块日志，并拒绝尺寸加法
溢出。C&C 的诊断为申请8,388,608字节、总空闲10,129,507字节、最大连续块
8,388,608字节；实际映射还需要对齐头，不能把总空闲量当作可分配的连续空间。
原生映射保留增长、尾部清零、失败保持和尺寸边界的宿主测试通过。

FW25 对照镜像大小3,926,736字节，SHA-256：
`b0ff9637f5d2977287ae7ffd90d13793199cb18481663fa3b2745543df661756`。
镜像含工作区原有的未提交图像适配代码，相关功能提交不是整个镜像的完整可重现版本。

SDK 提交 `79fd546` 在装载 AOT 前预留固定线性内存，使用尚未启用的空间暂存节
数据和重定位数组。所有借用释放后，实例化精确匹配并接管、清零；失败或尺寸
不匹配会回收。未改动 Guest ABI、权限或上游校验。普通及 ASan/UBSan 的读取、
预留、引擎回归和映射测试通过，包含临时内容污染及相同额外堆限额的对照。

FW27 的 OpenLara 0.2.7 真机回归成功：8MiB 预留被接管，临时借用280,584字节，
应用启动及音频就绪，原有四个应用版本保留。Quake II 0.1.6 的10.25MiB预留成功，
但模块装载仍报分配失败，故未提前上传约50MB资源。总8BIT空闲包含内部RAM，
不能当作PSRAM容量；启动以来累计最低空闲也不能当作单次加载峰值。

FW28进一步增加WAMR普通分配/重分配失败的尺寸、PSRAM空闲和最大连续块日志。
Quake II 0.1.7完成冷启动装载与固定映射接管，启动就绪时PSRAM空闲353,300字节。
原有四个应用版本保留，测试结束后确认OpenLara已活动并输出音频就绪。该阶段还
没有游戏数据，只是加载资格，不能将缺资源提示画面当作游戏关卡。
FW28对照镜像3,923,488字节，SHA-256：
`f2a744a053b3b6a733e7ed4cae76e467bdfc5d621afbbe4575845c0ae29272a9`。
加载器说明与边界见[SDK记录](../../deps/pxa-system/docs/zh-CN/wamr-pinned-load-memory.md)。

大资源传输的旧FSDATA出现一次单块应答相差79字节，不能继续把该临时文件的
前缀当作正确数据。已终止该次上传，新增可协商的`fs_chunk_crc32=1`与FSDATA2：
每块在写入前检查CRC32，拒绝时保留已确认前缀，CLI按确认偏移有界重试，最终仍
以整文件SHA-256决定发布。旧FSDATA及二进制传输兼容。

81项PXADB客户端测试通过，覆盖新旧上传、拒绝后的重发偏移及串口分段发送。
FW29真机主动注入错误CRC、截短数据、非法CRC、无效Base64和已有前缀后的损坏块，
全部被拒绝；确认偏移未推进，补传后9字节测试文件SHA-256一致，旧协议上传也通过。
原有四个应用版本保留并恢复OpenLara前台。约50MB的Quake II资源仍需完成单独校验。
当前FW29镜像3,923,952字节，SHA-256：
`17097d960b702311e0c63a11872c1fa2e83b02321452d9dcbbc330afbb3f8e6a`。

## 本轮候选与后续验收

Quake 连续字节读取快路径补充独立8KiB不可变页，避免批量读取换页后悬空；
顺序读取、跨页、交错批量读取、越界及 NVM 回归通过 ASan/UBSan。
真机计时确认主要瓶颈在渲染，增大ROM缓存未改善本场景帧率。光照插值与完整
曲面缓存仍为私有试验；像素正确性与设备性能分别验证，不把宿主速度当作真机收益。

两种着色缓存均未采用：0.1.3光照插值缓存的真机稳定中位4.9fps，低于5.9fps
基线；0.1.4曲面缓存也约4.9fps，提前终止。试验源与产物留在忽略目录，生产代码
已撤回。后续候选缩小经水位测量的栈和续体，预留由4降至3.5MiB，并细分渲染
阶段计时；标准Wasm批量内存操作仍是待设备对照的独立试验。

批量内存操作后续完成60个真机稳定样本，仍为中位5.9fps，已撤回到忽略目录，
不启用生产选项。曲面计时属于扫描计时的子集，不能把两者相加当作总渲染时间。

Quake II 保留7.5MiB引擎池，缩小经水位测量的 C 栈与续体缓冲，冷模型加载器使用
尺寸优化。协议宿主在实际关卡和重新开局中为10.1875MiB，保留完整图像、音频及
原容量上限。离线网络层取消无套接字时的服务器休眠，恢复原上游的立即返回语义，
避免本地10Hz服务器限制客户端渲染。真机资格与帧率须单独验证。

C&C 缩小栈后在协议宿主进入实际任务，线性内存6.125MiB，栈水位为
引擎6968、回调424、续体660字节；7MiB预留已使真机装载成功。
更低引擎池导致 Quake II 资源加载失败的试验，以及出现间接调用签名错误的
Red Alert ThinLTO 试验均没有采用。

公共SD读取使用两页缓存合并小于512字节的只读请求，按打开句柄隔离，关闭即失效；
大块READ_AT及私有可变文件走原路径。WASM回归覆盖连续读取、跨页、独立句柄、
关闭后复用、EOF、失败恢复和大块旁路。C&C同一协议宿主任务的READ_AT由5,065次
降至964次；缺失资源不查询不存在的包内Assets，加上小写路径后，控制请求从约
10,400次降至5,006次。C&C/RA SD的设置与存档也统一ASCII小写；普通变体保留
原有解析。计时改用单调时钟。相关游戏仓库提交为`b33bc37`，设备任务FPS仍须单独验收。

Red Alert当前S31代码7,192,392字节，大于当前内部可用安装空间；即便只删除本轮
测试示例也不足。它尚未完成设备装载。不能把只读资源已在SD上的设计称为代码也
可在SD安装，或为绕过容量问题删除原有应用。

## 存储与上游

资源固定放在 SD `/PXA/media/<AppKey>/`，不要求用户选目录。代码与私有存档
目前仍在内部；整应用 SD 安装及无 Flash 文件分区启动尚未实现。
已验证的系统字体迁移见 [固定 SD 字体](../design/pxa-system-fonts.zh-CN.md)。

平台适配尽量位于 vendor 外；少量引擎钩子使用编译条件保留原行为。
`common/recrof/tools/upstream.py` 提供上游检查、三方合并准备、冲突处理和应用更新；
2026-10-19复核四个上游 HEAD 均未变化。工具不会自动提交或推送，也不会替代
合并后的设备回归。


### 本轮新增：统一游戏手柄操作（真机验收待串口释放）

五款引擎及普通/SD 两种包统一接入12位 controller 0，FPS 菜单和游戏采用不同
映射，策略游戏支持光标、拖选、右键、地图滚动和快移。没有增加模拟轴 ABI，
现有接口仍是数字按键。公共映射和 RTS 适配器通过 ASan/UBSan；五款 WASM
构建、真实关卡输入与前后台回归通过，最后两处修复的最终回归也全部通过。Duke 0.1.23
ESP32-S31 AOT 已构建。

PXADB 新增可选 `INPUT CONTROLLER 0 connected buttons`，GameKit 在原50ms
上报路径交付完整状态，实体输入优先，CANCEL/KEY、断连、关闭服务或5秒超时
撤销测试状态。主机 CLI 保证长按结束释放，提供可重复的设备验证入口。

先前 UART 环形接收缓冲实际只有256字节，现通过安装包装只将 PXADB 共用端口
提升到4096字节，保留既有 console/VFS 绑定。FW30 真机 HELLO 验证4096，五种
坏分块均拒绝且不推进已确认前缀，完整 SHA 与旧协议复验通过。大的接收环不
代表硬件 FIFO 可以接受任意突发；主机仍保留128字节分段和旧的512字节默认
分块，未采用尚未证实可靠的512字节突发或1024字节默认分块。

带手柄诊断入口的新固件已构建；刷写尝试在打开串口时被独占锁拒绝，没有开始
写入。当前占用者为另一个 OpenLara 真机验证任务。新增固件和 Duke 控制器真机
验证已按串口独占顺序准备，等待占用者释放；不会打断或终止其他任务。
Quake II 大资源传输仍未获得完整 SHA 通过，Red Alert 真机关卡也仍待验收。


串口自然释放后，FW32 真机刷写及分区表核验通过：固件3924960字节，SHA-256
`23fc4bc2d90d54007c21283e7c3b8be9f87bb68a571113af1a51552b479c1f04`。
手柄入口7项合法/非法状态检查、4096字节实际接收缓冲、5项CRC故障注入与旧协议
复验通过。保留并恢复此时原有的 OpenLara 0.3.5，Store 0.8.8、Voxel Craft 0.12.8、
Jump Jump 0.1.7 未变。Duke 0.1.23 新AOT的安装及真机手柄/帧率测量正在进行。
以上是固件入口验收，不是五款游戏的真机性能验收。


### 用户反馈上下键无效：Duke 0.1.24 已真机修复

0x48/0x50并不是ESP入口直接消费的引擎 sc_UpArrow/sc_DownArrow（0x5a/0x6a）。

最低11.9）仅保留作原始游玩记录，不作静态性能优化归因。

GameKit / ESP32-S31 上0.1.24的安装和功能验收通过：前进位移(1202,5177)，
后退位移(-1888,-6445)，点积-35635141，确认实际产生相反方向移动；菜单从

保留，当前 OpenLara 为其他任务已更新的0.3.6。修复包保持Duke关卡前台，供用户
直接按实体上下键验证，自动切换其他游戏的队列已取消。

修复包AOT SHA-256：
`ee4a0a8657f899648208e9733b388dc5adb5f68da8a98ce7a41926a6b3135b91`。
