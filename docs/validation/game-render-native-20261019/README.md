# GameRender 原生光栅重构：2026-10-19

本轮落地 GameRender 1.0 的计算上下文、受限借用内存、原生 INDEX8
光照 span 和 C/C++ SDK。**目前没有达到 Quake 20fps，原生 span
适配默认关闭。** 该实现是已验证的计算接口基础，尚不是完整的高性能
游戏渲染后端。

## 已完成的边界

- Raster 实现从 Surface 目录迁到 GameRender；Surface 继续负责已有帧的显示。
- `CREATE_RASTER_CONTEXT` 不创建显示层、纹理副本、帧/深度缓冲或命令邮箱。
- `EXECUTE_SPANS` 整批校验范围、精度、光照、别名和工作量，再开始写入；
  失败不会留下部分输出，适配器能在表面状态失效前回放原内核。
- WAMR 每次同步导入解析当前线性内存，离开导入即撤销借用；
  不要求固定内存，也不把 Guest 指针保留到返回之后。
- ESP 复用原先的光栅 worker。按互斥字节区域分工，保留同一像素的命令顺序，
  加入所有 worker 后才返回。worker 的既有 4096 字节栈位于 PSRAM。
- Host/C/C++ 的 span 布局由同一 JSON 生成。C 调用者提供存储；
  C++ 通过 RAII 管理上下文。统计区分校验、执行、像素和拒绝次数，
  不把这些数值解释为显示帧数。
- GameRender 服务主版本从 0 改为 1；旧的 GameRender 客户端需要重新打包。
  ESP 和桌面产品的能力声明一并更新。允许计算上下文与一个显示上下文并用。

## 验证

`native-device.json` 对应唯一测试设备 GameKit / ESP32-S31，
序列号 `1c:29:04:d0:af:5e`，16MiB PSRAM。刷写仅涉及 `0x10000` 应用分区，
分区表哈希与原先一致，未格式化文件系统或擦除 NVS。最终固件 SHA-256：
`d5d63d4f207a0eedfd76d662c8468b99dd7601ad745b43d167959270fd65eb78`。

真机计算测试执行 8 批、512000 像素，旧目标和扩容后的新页面共验证
128000 个最终像素，差异为零。第 5 批前执行未固定内存的 `memory.grow`，
随后把输出移到新提交页面，验证 Host 获取了新的范围与基址。
Host 的 frame、scratch、mailbox 计数均为零；Guest 仍提供输出和只读资源。
该轮累计校验 1568us、执行 56280us；包含双核调度与加入，**不是游戏 FPS**。
桌面正式签名包也通过了相同扩容与像素检查。

Host/WAMR 43 项测试通过；C SDK 测试通过；C++ SDK 以分段运行覆盖，
包括 UI/服务诊断、GameRender 服务与新 span 帮助类。没有声称做过一次
完整无中断的 C++ 全量测试。上游同步等公共适配回归 23 项通过。
`differential.txt` 直接提取当前锁定 Quake 源码的原始宏，完成
200000 组 / 400000 条 span 的一致性检查，覆盖八种内核、负坐标、
有序重叠、随机分区和输出守卫。ASan/UBSan 检查新 Host 实现；
上游参考函数保留其原有负数左移行为，仅对参考函数关闭 UBSan。

汇总规范检查通过（52 个 Core 向量、5 个包载荷）。审计清单已对齐
已经实现的 Clock 0.3 / FS 0.3，并修正 FS 协议标签与 service 字段不一致；
没有改变它们的运行时协议。新 codec 的生成检查和现有 wire 向量通过。

## 性能限制

Quake 的原生 span + 标准编译器、原生 span + 私有对齐编译器/固定全局
寻址两组，均在实际 `start` 地图出生点记录 60 秒，面板 FPS 中位数 3.9。
配套 JSON 保存每秒采样；截图在计时窗口之外取得。测试每秒注入中性
手柄状态保持设备唤醒，没有把菜单、演示或熄屏时的零值计入这些窗口。
另一次未保持唤醒的窗口已作废，未作为性能结果。

Quake Guest 批次固定占用 6216 字节，当前仍逐表面提交并在 Guest 中
计算透视步进及写深度。这种细粒度封送未产生帧率收益；SDK 默认
编译器没有替换，对齐实验也未解决该问题。后续需要测量更大粒度的
透视/深度工作提交，避免继续增加短 span 的导入与编码开销。
当前没有实现 INDEX8 直接显示，也没有取得减少 RGB565 双缓冲的收益。

Quake II 恢复上游单精度常量语义：Clang 使用
`-Xclang -cl-single-precision-constant`，IR 检查确认隐式浮点表达式
采用 f32，显式 double 仍采用 f64。该代码生成证据本身不代表设备帧率。

新光照内核保留来源和 GPL-2.0-or-later 文件级许可，见 SDK 的
`libpxa/THIRD_PARTY_NOTICES.md`；没有把上游代码重新标为 MIT。

关闭原生 span、启用固定全局状态直接寻址、使用标准 AOT 编译器的
60 秒对照达到中位数约 6.9fps（`quake-direct.json`），仍未达标。
该寻址优化没有改变数值算法，现作为默认配置；未启用私有对齐编译器。

额外的同像素数粒度对照（`granularity-device.json`）：200 次每次
320 像素的调用累计 25196us，其中校验 7502us、执行 10952us。
与单批 64000 像素相比，小批次同时增加封送/导入成本并降低双核
收益；这些仍是离屏计算数据，不是关卡 FPS。

Quake II SD 0.1.13 已进入真实 `base1` 关卡，`prepped`/连接/菜单状态
通过引擎记录确认，计时窗口在截图和加载之后。60 秒中位数 7.4fps、
最低 6.9、最高 7.9；没有达到 20fps。前后控制有可见响应。
线性内存上限 163 页（10682368 字节），arena 仍为 7864320 字节，
本场景 arena 峰值 7850704 字节。测量后 PSRAM 剩余 343604 字节，
不能据此承诺其他地图的装载空间。详见 `quake2-device.json`。

差分检查另以 Clang + ASan/UBSan 重跑并通过同样 20 万组；
与 GCC 的结果一致，详见 `differential-clang.txt`。

Quake 的渲染相关文件（`d_*`、`r_*`、共享 mathlib）也单独试过
单精度常量，60 秒中位数仍为 6.9fps（`quake-float-experiment.json`）。
没有把这项无明显收益的精度调整加入公开构建，保留原数值算法。

迁移回归：Voxel 的原生输入、世界、渲染、持久化与声音测试全部通过，
公共 C++ 游戏测试中的 raster 目标也从新路径构建通过。只更新当前
构建入口；历史性能补丁和溯源文件保持当时的路径。
