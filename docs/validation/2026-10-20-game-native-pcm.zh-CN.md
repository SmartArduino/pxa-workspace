# GameKit 原始 PCM 与 Core 2.1 实机集成

本记录是阶段性证据。五个游戏的稳定实测 >=15fps、完整实机音频验收尚未完成，
不能把编译通过或 Node 帧数作为达标结果。

## 代码与产物

- SDK `b787d4a`：Audio 0.10 精确源格式会话及有界重采样。
- Apps `5281572`：保留源双声道 PCM，支持 Core 2.1 主循环。
- Host `2760f15`：GameKit 按 48kHz 设备时钟直接拉取混音输出。
- 本轮附加修复：先撤掉启动遮罩，再进入可能长期保留调用栈的 Guest；
  PXADB INFO 返回完整 ELF SHA-256；主循环探针拒绝历史日志和被遮罩覆盖的画面。

`tools/game-perf/profiles/*-native-pcm` 是显式选择的实验配置，沿用各游戏的
正式 SD 包 ID、发布者及固定资源路径。它们保持原渲染器默认选项，要求 Core 2.1、
Audio 0.10，不使用 Asyncify continuation。五个签名容器及 AOT 均已生成，
大小和完整哈希见同名证据目录的 `artifacts.json`。

Quake、Quake II、Duke 的源音频为 11025Hz 双声道，C&C、RA 为 22050Hz 双声道。
GameKit 的物理输出是 48000Hz 单声道，在 Host 输出边界有界转换。新增混音工作区
在 PSRAM 分配；不增加一个独立混音任务。源格式被接受不等于物理扬声器连续播放
已经验收，后者仍需逐游戏验证。

- 主循环探针的五项 Python 校验正常及优化模式均通过，包含历史日志、重复心跳、
  其他应用日志及启动遮罩的负例。
- GameKit `1c:29:04:d0:af:5e` 的三个主循环周期通过：前后台、手柄、触摸、

## 安装与后续测量

已校验 Quake SD PAK 的实际 SHA-256，并安装 `pxa-quake-sd` 0.4.10。
为保留有限 Flash 空间，旧 Quake II 代码先完整导出、哈希校验，再使用
`PACKAGE archive` 保留数据卸载；主循环探针同样归档。NES 与 OpenLara 未卸载。
完整应用直接安装 SD 仍是尚未完成的独立存储能力，不能从 SD 资源读取推导已经实现。

Quake 前两次启动采样受到 USB 桥断连影响，未取得有效测量窗口。
第一次重连时 MCU uptime 持续且 Quake 仍在运行；Linux 同时记录 USB 桥重新枚举。
第二次加入只读 usbfs 保活仍断连，内核后来还报告 hub port 被禁用并重启。
这些运行不作为帧率或游戏崩溃证据。后续仅接受固件身份一致、实际关卡 ready、
持续新日志及完整采样窗口的结果。

第三次运行完整通过采样：Quake 起始大厅，默认 320×240 渲染，生命值 100，
坐标 `544,288,50`。60 秒共 60 次 FPS 查询，中位数 **7.9fps**，
平均 **7.63fps**，范围 **6.9–7.9fps**。12 条去重的真实关卡 ready 日志跨越
55.798 秒，结束时仍有新 ready 记录，采样期间不抓屏、不移动镜头。
当前仍然**未达到 15fps**。运行后 SRAM free 91795 字节、PSRAM free 9160364 字节；
源 PCM 11025Hz 双声道、输出 48000Hz 单声道协商成功。正常退出、清理无错误。
截图、原日志、采样脚本和窗口审计保存在 `quake-baseline/`。

这个固定场景的渲染约 102–104ms/帧，其中表面绘制约 66–68ms/帧，
仍是主要瓶颈。主循环与 PCM 改造不能单独证明性能目标已经实现；
后续编译器和渲染器优化必须与这份实际基线比较。

## 编译器对照与 Quake II 实际关卡

隔离 WAMR 工作树应用 `tools/game-perf/wamr-known-alignment.patch`，
正式 SDK 编译器未改动。使用上面的**同一个 Wasm 文件**生成 Quake 0.4.11/seq131，
保留原有 bounds/overflow 检查。RV32 指令及 x86 非对齐、边界执行检查通过，
完整编译器/补丁/输入/输出哈希见 `quake-aligned/recipe.json`。

同一固件、同一默认 START 出生点，60 秒连续采样的对比如下：

| Quake 候选 | 中位 FPS | 平均 FPS | 最低–最高 |
| --- | ---: | ---: | ---: |
| 原始 PCM / 主循环基线 | 7.9 | 7.633 | 6.9–7.9 |
| 仅 AOT 可证明对齐优化 | 7.9 | 8.367 | 7.9–8.9 |

优化窗口有 12 条去重关卡状态，设备时间跨度 55.928 秒。渲染耗时中位数
92.766ms、表面绘制 59.177ms；AOT 从 2998820 降至 2986468 字节。
这是一组顺序 A/B 诊断，不能据此宣称已经稳定达到 15fps，也未将实验编译器
设为 SDK 默认。源码、截图、完整窗口和采样脚本保存在 `quake-aligned/`。

Quake II 0.1.15/seq16 已实际进入 Outer Base，HP100。首次短等待不足以完成
关卡加载，未记为性能窗口；随后带加载进度的独立运行约 174 秒收到首次真实关卡
状态。画面曾显示引擎的加载超时提示，最终完成资源加载。
进入关卡后的首个 60 秒窗口中位 **6.9fps**、平均 **6.783fps**、范围 **1.9–7.9fps**；
该窗口紧接首次 ready，仍可能包含首次贴图/模型工作，不作为稳态达标证明。
11 条去重实际关卡记录跨越 51.009 秒。采样后逻辑手柄向前、向后分别使坐标
从 `1024,-2560,193` 变为 `623,-2159,193`、`1118,-2706,193`。
这是路由注入的逻辑手柄测试，不代表所有实体手柄的电气输入均已验证。

Quake II 测量后 SRAM free 125507、PSRAM free 1905268 字节。
引擎 arena 总量 7864320、加载峰值 7850704 字节，仅余 13616 字节；
这揭示了后续关卡/资源组合的内存风险，尚不能视为足够的通用余量。
源 PCM 保持 11025Hz 双声道，固件未重启。证据见 `quake2-baseline/`。

## Duke3D 实际关卡

Duke 0.1.32/seq33 已进入 E1L1 Hollywood Holocaust 的屋顶。默认渲染与
11025Hz 双声道源 PCM 下，60 秒中位 **16.9fps**、平均 **16.527fps**，
范围 **14.9–17.9fps**；有一次读数低于 15，因此保留这个低点，不将它描述为
所有窗口均稳定超过 15。十条去重的 `mode=4` 游戏状态跨越 55.312 秒，
采样时位置保持 `-31243,7160,-158228`。

采样后逻辑手柄向前使位置变为 `-30041,12337,-158422`，向后回到
`-31552,6843,-158367`，对应截图均为实际关卡。测量后 SRAM free 87647、
PSRAM free 9658624 字节，正常停止、清理无错误。原始证据见 `duke-baseline/`。
该场景已接近最低目标，仍需要余量及移动/战斗窗口的检查。
