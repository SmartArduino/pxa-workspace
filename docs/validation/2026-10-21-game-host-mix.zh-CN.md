# Audio 0.11 同步 Host 混音候选

本轮实现了可调用的 Audio ABI、C/C++ SDK 和 Quake 候选适配，并完成原生
正确性检查、ESP32-S31 固件与 AOT 构建。**尚未在设备上运行这条新路径，
没有新的 FPS、音频听感或运行时堆内存结论。** 普通 Quake 构建默认关闭它。

目标 GameKit 的只读检查显示 NES 0.1.23 正在运行。关于是否可以中断这项测试
的确认仍未得到明确答复，本轮没有发送停止、安装或刷机命令。设备身份为
`1c:29:04:d0:af:5e`，USB 序号为 `5CFF043509`。另一项 NES / GameRender
工作仍在修改共享目录，提交只包含本轮 Audio 和 Quake 文件。

## 实现范围

Audio 0.11 `MIX_PCM` 在一次同步调用内读取当前 Guest 的线性内存，累加到
已有 S32LE 双声道缓冲。支持 S8、U8、S16LE、单/双声道、左右线性增益和
Q16 最近邻采样位置/步长。最多 32 个 span、4096 个输出帧，单次总工作量
最多 16384 个 span 帧。整批校验完成后才写入；越界、重叠、错误格式、
保留位或工作量超限均不改变目标数据。

没有新增线程、堆分配、常驻 PCM 副本或会话状态，也不会持有跨调用的 Guest
指针。调用继承现有 Audio 会话的所有权和生命周期；它只做计算，不提交播放
或推进播放计数。原有 PCM FIFO、重采样、系统增益和输出任务保持原实现。
上一轮 reciprocal 重采样候选未合入，本固件仍使用 `ab1764b` 的 PCM 内核。

Quake 适配在原函数加载采样、将左右音量量化到 8 的倍数之后调用 Host。
原引擎仍负责时间、循环、主音量、S16 饱和和最终 U8 输出量化。每次加载后
立即提交一个 span，避免为了跨声道组批而保留会被复用的临时采样地址。
ABI 的批量能力不代表这个 Quake 候选已经跨声道组批。Host 拒绝时回退原循环。
这也不代表异步 Host 声部、Duke MultiVoc 或 OPL 合成已经迁移。

上游差异只包括条件钩子和平台适配；差分测试直接提取当前 vendor 的原混音
循环。以后使用三方合并同步上游后，应重新运行此测试。

## 验证

- Quake 原混音循环 8192 组比较通过：1..8 声道、1..1024 帧、全部音量
  量化档、正负满幅及双声道累加输出。
- Host 内核覆盖三种编码、源地址不同字节对齐、单/双声道、分数位置和步长、
  正负 S32 饱和、32 个 span 的上限，以及后续非法 span 不得写入前序结果。
- Core 测试通过真实 Audio 会话与借用内存入口执行，检查调用外无法借用、
  关闭后的句柄失效。原 PCM mixer 回归通过。
- C、C++ SDK 的 wire 编码、结果长度、错误传播及非法参数本地拒绝通过。
  C++ 使用 SDK 要求的 C++26 和 `-O2`；检查运行在 ASan/UBSan 下。
- SDK 规范与生成文件检查通过。为避免混入并行 GameRender 的版本改动，
  在 `422c982` 的独立副本上仅叠加本轮 Audio 变更检查。
- GameKit 固件链接、镜像生成与分区容量检查通过；两份 Quake RISC-V AOT
  包的导入和线性内存验证通过。

原始结果和哈希位于 [证据目录](game-host-mix-20261021/checks.json)。

## 尚待实机完成

先验证前一轮手柄保序修正在设备上对短按和上下移动的实际效果，再做 Duke
重采样候选与 Quake 同步混音的独立对照。测量必须固定固件、资源、实际关卡、
控制器状态及完整采样窗口，同时记录 FPS、音频处理时间和 SRAM/PSRAM。
出现回退时不能将结果视为 Host 混音性能；新 Quake 候选首次真正执行成功会
记录 `PXA AUDIO Host S8 accumulation active`。

Quake 之前的主要瓶颈仍是渲染；这次混音内核的正确性和内存结果不能推导出
20 FPS。目标继续保留，设备对照前不默认启用候选，也不宣称四款游戏已经达标。
