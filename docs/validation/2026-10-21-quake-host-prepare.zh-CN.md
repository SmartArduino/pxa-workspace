# Quake：有界投影预计算与光照缓存

本轮以同一台 GameKit 的 Quake START 出生点为实机验收对象。保持原来的渲染尺寸、
采样、光照、深度和音频源格式。Host 增加可选的有界投影计划；Quake 增加按实际
网格尺寸存储的光照缓存。性能选择以 LCD 完成帧数为准。

源码提交：SDK `bd1d8ebd182573da16a9d522b60a8a32cc00ca1a`；
Quake Apps `05669b790d77e6f5cfa70cf1c9309b01ce217a82`。提交前另外导出 SDK 暂存树，
独立运行 ASan/UBSan 下的正常分配和分配失败回退测试，均通过。

## 设备、隔离和复现

- USB `5CFF043509`，MCU `1c:29:04:d0:af:5e`，`doit-gamekit` / ESP32-S31，
  320 MHz，16 MiB PSRAM，320×240 LCD。
- 固件基线 ELF `a8e8925070ee547ad0e9592563cfa0be447b0121d769b58cc73d9d93733b42aa`。
- 最终固件 ELF `e76d8ad9ff9952f8d333a0e7971afae713c21bbe31c39569af82647941b91324`。
  `CONFIG_PXA_GAME_RENDER_PREPARE_KIB=0`，保留可选能力，默认不分配投影工作区。
- 固件以此前冻结的已验收源码为底，只叠加本轮改动。当前工作区另有其他设备、
  显示及 GameRender 1.3 改动，不能把整个混合工作区视为本轮刷入的镜像。
- 本报告只提交配置、结果和复现步骤。原始串口日志、截图、构建日志及实验快照
  保留在本地 `build/quake-host-prepare-20261021/` 和
  `docs/validation/quake-host-prepare-20261021/`，后者已加入忽略列表。

刷写前核验 USB、MCU、原 ELF、分区和镜像哈希，只写 application 分区。
安装空间不足时只归档本任务的 Quake 程序，保留资源与私有数据，再安装签名目录。
其他应用及另外两台设备未作修改。测试工具见 `tools/game-perf/run_quake_host_probe.py`。

所有主对照固定应用目录集合和 AOT，在每次测量前冷启动。进入新游戏，预热后
统计 60 秒 LCD 完成帧数；要求 HP=100、位置 `544,288,50`，至少 8 条新的关卡
记录跨越 45 秒。恢复丢失的日志时按设备原时间戳去重。截图和输入操作放在计时
窗口之外。瞬时 FPS 样本不能代替完整窗口的累计完成帧计数。

## Host 预计算对照

下表使用同一个私有 Quake 0.4.20 AOT。模式 7 开启原生世界批次、原生显示转换
及光照缓存；模式 5 使用 Guest 世界渲染和相同缓存。模式 1 关闭光照缓存。

| 固件 / 路径 | LCD FPS | 验证 µs/帧 | 执行 µs/帧 |
| --- | ---: | ---: | ---: |
| 原 Host，模式 7 | 7.4951 | 11,038.5 | 16,807.5 |
| 预计算、独立统计遍历，模式 7 | 7.5785 | 14,519 | 12,736 |
| 合并工作量统计遍历，模式 7 | 7.7616 | 13,985 | 12,867.5 |
| 原 Host，Guest 世界 + 缓存，模式 5 | 7.9087 | 75 | 2,833.5 |
| 原 Host，Guest 世界，模式 1 | 7.7783 | 80 | 2,838.5 |

验证和执行列为区间“每引擎帧均值”的中位数，含原生显示转换。它们与 Guest
内部阶段存在包含关系，不应把各阶段相加。最后两行只在 Host 做显示转换，不能
与原生世界行比较单列后宣称整个引擎被加速。

预计算把 Host 执行阶段缩短约 **23.4%**，但增加验证阶段的存储及计划构建成本。
整帧只提高约 **3.6%**，仍未超过同包的 Guest 世界路径。因此普通 Quake 保留
Guest 世界渲染，Host 预计算默认关闭。不能把此内核收益表述为达到 20 FPS。
区间数据和原始记录保留在上述本地实验目录。

## 接口与内存约束

- Guest GameRender 包格式和 opcode 不变。SDK 增加 Host C 的 `*_spans_prepare()`
  和工作量分界查询；`pxa_game_render_config_t` 可指定预算分配器与工作区容量。
- 验证和投影一次完成后，计划保存每行的颜色/深度位置，以及每 32 像素的四个
  16 位采样参数。工作量统计在写入计划时完成，避免再遍历 PSRAM。
- 完整验证成功才发布计划。非法末条命令整批拒绝；容量不足丢弃计划并走原路径。
  首次分配失败不会每帧重试；context 关闭时释放。不存在跨调用的 Guest 指针借用。
- 双核复用原 worker，以工作量分段、实际执行耗时和缓慢调整的份额决定分界；
  保留原有领取/接管协议。没有新增任务、任务栈、帧缓冲或纹理副本。
- ESP 可通过 `CONFIG_PXA_GAME_RENDER_PREPARE_KIB` 选择 0–1024 KiB，默认 0。
  96 KiB 实验配置只使用 PSRAM，计入 raster 预算的实际分配为 98,320 B，禁止
  回退到 SRAM。最终默认配置不产生这项分配。
- 最终固件相对基线 `.flash.text` 增加 2,136 B；静态 DRAM、IRAM 和外部 BSS
  段尺寸不变。服务 context 的动态元数据另计，静态段数据不能代表堆或栈峰值。

SDK 使用和生命周期说明见 `deps/pxa-system/docs/zh-CN/game-render-preparation.md`。

## Quake 光照缓存

最终缓存为 256 组、每组两路，元数据和 96 KiB 数据池共 **120 KiB**（设备 ABI）。
数据池按实际光照网格尺寸占用，复用已有槽位，耗尽时先失效全部标签再复用空间。
没有渲染循环堆分配。缓存位于 Guest 的 PSRAM 线性内存；固定最大值仍为
3,670,016 B（56 页），相应减少 Guest 内可用堆空间。

键包括 surface、mip、光照样式系数、环境光和网格尺寸。地图切换清空，动态光照、
全亮及不支持的网格直接使用原引擎。大块网格读写复用已有 `memory.copy` 路径，
小块仍使用普通复制。它缓存原引擎的光照数据，保持原像素采样和量化。

验证模式对每次命中重新执行原引擎计算，逐字比较所有实际采样的打包字段。
上游打包循环按两个元素处理；当有效行长度为奇数时，会将网格后方的 scratch
写入末行的一个不参与采样的高半字。验证器单独统计这类末行差异，仍严格检查
全部有效采样行。离线直接执行当前 vendor 的打包循环，在 289 种网格中复现
72 种这类边界；实际采样行完全一致。

早期 0.4.17 验证器比较了整个未使用末行，实机主动停止并报告差异；没有以该
版本作为生产配置。修正后先完成 39,801 次比对，再用有界数据池版本完成
99,153 次比对，并通过短按、前进/后退、悬浮按钮切换和正常停止。
最终版本的独立验收记录补充在下文。

### 最终缓存的同包对照

使用同一个 0.4.23 AOT、最终固件和冷启动，依次测量开启、关闭、再次开启缓存。
这组 AOT 启用了 bulk copy，并将缓存从 256 个条目扩展到 512 个条目；不能将
它与上表 0.4.20 的差值全部归因于缓存开关。

| 模式 / 顺序 | LCD FPS | view µs/帧 | load µs/帧 | pack µs/帧 |
| --- | ---: | ---: | ---: | ---: |
| 5，开启 | 8.2943 | 95,317 | 7,870 | 2,809 |
| 1，关闭 | 7.9442 | 100,136.5 | 12,384.5 | 5,743.5 |
| 5，再次开启 | 8.2613 | 95,590 | 8,853 | 2,715.5 |

本场景两次开启的 LCD FPS 分别提高 **4.41%**、**3.99%**；因此普通包启用光照
缓存和批量复制。这里只是一个固定关卡场景的短窗口结果，不代表所有地图。
独立验证模式完成 **154,915** 次实际光照网格命中比对，无有效采样字段差异；
同次运行完成 150/100/50 ms 手柄短按、前进和后退、触摸/手柄悬浮按钮切换。
8,089 次未采样末行差异单独记录，没有计入有效字段正确性。

数据见 `cache-final-verify`、`cache-final-mode5-retry`、`cache-final-mode1` 和
`cache-final-mode5-repeat`。首次独立重启后出现一次 PXADB HELLO 超时，当时未启动
应用，保留失败记录且不计入帧率。之后使用同一串口描述符完成冷重启、启动身份
核验和探针连接，全部窗口通过。

## 回归和上游更新

- Quake 当前 vendor 投影、光照、深度：40,000 组逐字节比较，含普通、预计算、
  工作区耗尽、拆分范围、负偏移、重叠写入和八种采样内核。
- 原生光照跨度：200,000 组比较、400,000 个跨度。
- SDK：0–4096 字节容量、16 种起始偏移、保护字节、目标范围扩大、反向执行、
  预算分配失败及关闭释放；ASan/UBSan 下通过。
- 光照缓存：1,024 个 surface/mip 周期、20,000 次池复用访问、样式/环境光变化、
  动态光绕过、地图重置和失效；原生 ASan/UBSan 与实际 WASM bulk 路径均通过。
  原生测试另验证有效采样字段不一致必须报错。
- 批量读取：2,048 种复制，覆盖阈值、所有字节对齐和边界；WASM 批次回退：
  256 个拒绝批次、768 个材质重放原颜色和深度。
- ESP adapter host suite 通过。新的 sampler 不改音频混合；实机继续核验
  11025 Hz 双声道 S16LE 到 Host 48000 Hz 单声道的协商。未采集物理音频波形。

平台缓存实现放在 `quake/port/`，vendor 只保留加载、打包和换图处的小型接入点。
既有三方同步工具已对锁定提交 `b4c8c22bae3298b98c02166116eaeb91a34ffc24` 重放：
0 个上游修改、0 个冲突，适配补丁包含这些接入点。这不表示验证了新的上游提交。
更新上游后应重新运行上述原函数差分与实机检查。

应用、Quake 的 PAK 与私有数据。程序 AOT 为 3,016,860 B，最大线性内存仍为
56 页。普通包没有运行时渲染探针和原生世界批次代码。AOT SHA-256：
`1fe1a99541667cb4474da597b10fbece90ff1629963e785a4896937822bc4ca0`。

私有对照包不同，不能将二者差值当作缓存收益。缓存的受控收益仍以上面的

- 150/100/50 ms 手柄短按的 Guest 按下/释放边沿均通过。
- 前进从 `544,288,50` 到 `544,418,46`；后退到 `544,292,50`，方向相反且实际移动。
- 触摸显示悬浮按钮，手柄操作隐藏，断开手柄后恢复；各次截图检查通过。

## 剩余瓶颈

普通包窗口的阶段中位数为：`view` 86.52 ms、`scan` 63.86 ms、`surf` 52.33 ms、
资源读取 `io` 15.23 ms、Host 执行 `hx` 2.90 ms、音频 `snd` 1.97 ms。
这些是含子阶段的引擎计时，不能相加。要达到 15/20 FPS，整帧预算分别只有
66.7/50 ms；当前世界渲染本身就超过预算。

下一轮应先减少 Guest 材质准备和采样中的重复工作，结合 AOT 指令查看非对齐
访问成本，再核对虚拟 Flash 缓存未命中和 SD 读取次数。若继续迁移到 Host，
必须同时降低 Guest 批次生成、复制和验证成本；只优化执行内核无法兑现整帧收益。
现有音频阶段占比较小，应保留正确性并以实际新瓶颈决定是否继续迁移混音。

本轮最终选择：开启有实测整帧收益的光照缓存和批量复制；保留预计算 API、
有界 PSRAM 配置和双核工作量划分，但默认关闭尚未胜过 Guest 的原生世界路径。
