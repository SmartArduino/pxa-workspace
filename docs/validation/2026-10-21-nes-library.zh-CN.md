# NES 多游戏性能优化：0.1.33 / release 39

本轮以实机性能为主。对照 0.1.32，炸弹人、魂斗罗、忍者龙剑传1 的 LCD 完成帧率提高约 15%–22%；重装机兵小幅提高，忍者神龟3 基本持平，马里奥本轮下降约 2.6%。不能将这些结果描述为所有游戏都提速或全部达到 60 LCD fps。

## 同机对比

DOIT GameKit-1 / ESP32-S31，序列号 `1c:29:04:d0:af:6a`，固定 by-id 端口 `usb-1a86_USB_Single_Serial_5CFF040750-if00`，2,000,000 baud。固件保持上一轮版本，ELF SHA256 `4d22ba1b0a7f83867e214ee408806590e72e857605c305c144770a5fbe0a7e97`。同一编译工具链、同一 ROM 集合和测试身份 `pxa-nes-library`，正式身份及存档隔离。

下面是相同加载、启动及输入脚本下的场景测量，包含场景随运行时间发生的变化；不是逐模拟帧同步的对照，也不代表整个游戏的固定帧率。声音开启，控制器逻辑注入后悬浮按键自动隐藏，画面 256×240 原像素居中于 320×240 Surface。

| 游戏/场景 | 0.1.32 LCD fps | 0.1.33 LCD fps | 变化 | 模拟 Hz |
|---|---:|---:|---:|---:|
| 炸弹人／迷宫 | 35.49 | 43.28 | +21.9% | 60.02 |
| 魂斗罗／丛林 | 19.28 | 22.66 | +17.5% | 60.05 |
| 忍者龙剑传1／1-1 | 26.78 | 30.80 | +15.0% | 60.01 |
| 忍者神龟3／海滩 | 21.79 | 21.97 | +0.8% | 60.02 |

表中 LCD fps 来自固件 `PERF START display` / `PERF STOP` 的 `completed × 1e6 / window_us`，统计面板传输完成次数，不使用 Guest 提交数代替，也不是光学测量的面板扫描频率。LCD 计数窗口约 25–30 秒，包含预热；内核和模拟速度取预热后 3 个约 5 秒的新日志窗口。马里奥这份 ROM 是 PAL，正确目标为 50Hz。

原始对比、各项耗时与日志见 [hardware-comparison.json](nes-library-20261021/hardware-comparison.json)。`baseline-clean2-*` 和 `candidate-c-*` 子目录包含完整日志、结束画面及计数窗口。截图在计数窗口之外采集；入口截图后暂停/清空音频积压/恢复再预热，减少截图运输造成的干扰。控制器注入不是机械按压；结束执行 `INPUT CANCEL` 恢复 GPIO 上报。

## 改了什么

1. **合并只读零页等待循环。** 原来的绝对 `JMP` 自跳转之外，新增 `LDA/LDX/LDY zp; BEQ/BNE -4`。实时检查代码映射、读处理器、指令、当前变量与分支条件，只合并当前 CPU 预算内的完整迭代，最后的部分迭代仍交给原解释器。保留寄存器、标志、跨页周期、DMA、IRQ/NMI 边界，使用解释器自身的零页指针。没有按游戏名或固定 ROM 地址启用，也没有丢模拟时间。
2. **减少 PPU 名称表查询。** 同一背景区间复用名称表页指针，水平跨表及 Mapper 锁存回调后刷新。图块位平面仍实时读取，避免图形银行切换后使用旧数据。
3. **先排空再处理 PCM 溢出。** 一帧计算期间 Host 可能腾出音频空间。Guest 队列即将溢出时先重试写出，再决定是否丢弃；普通情况不增加写入调用，也不扩大 256ms 缓冲。

沿用上一轮 Host 双核绘制、PCM 和 LCD 传输路径，本轮没有增加帧缓冲、扩大 4MiB 固定线性内存或替换设备固件。以上帧率属于合并改动的结果，没有将总收益错误地归给某一个改动。

## 慢在哪里

原生指令计数用于找热点，不能换算成开发板耗时。炸弹人固定输入段中，两组只读零页等待占约 79.8% 的执行指令；忍者龙剑传1 的一组等待占约 57.3%。这些循环适合本轮合并。魂斗罗的热点含有持续修改 RAM 的运算，本轮不会把它当成空等直接跳过。

实机中，忍者神龟3 生成视频帧的内核调用平均约 **18.60ms**，不生成视频的内核调用仍约 **10.87ms**，视频转换/提交前绘制约 **2.87ms**。NTSC 每帧只有 16.67ms，持续维持 60Hz 模拟必须跳过一部分视频输出。内核时间包含 CPU、PPU、APU 及可能的 Host 抢占，不应称为纯 PPU 时间。下一轮应优先减少这类场景的 CPU 总线与 PPU 绘制成本。

炸弹人的生成视频帧内核调用降到约 11.84ms，但转换约 3.4ms，仍记录到 Surface 缓冲背压。快速场景还需要继续检查缓冲归还、显示准备和 Host 调度。单纯把“提交”改成“直刷”，无法消除上述内核计算成本。

马里奥本轮 43.72→42.58 LCD fps，属于本轮观察到的小幅回退；本轮没有证明它获得收益。忍者神龟3 的 +0.8% 也不应视为明确提升。

## 其他场景与音频

自动脚本的截图复核发现：忍者蛙初次窗口混入标题/演示，《1943》初次停在分配属性界面。这些数据仍保存在原始结果中，但不纳入上面的实际游戏场景提升结论。《1943》属性界面 35.23→45.55 LCD fps 不能表述为战斗帧率。

寻秦记的开场剧情窗口为 46.03 LCD fps、约 60Hz 模拟；这是新增 Mapper 241 后的测量，没有旧版可运行基线，也没有据此宣称战斗性能。

忍者蛙从关卡开始的 60 秒日志长测，平均模拟 **60.004Hz**，积压为 `1,1,0,0,1,0,0,0,1,0,0,0`，音频丢样为 0；LCD 整个窗口约 **25.54fps**。截图确认起点是战斗，但末尾已死亡返回标题，所以这个平均值只用于检查跨场景的运行稳定性，不能作为纯战斗帧率或与初次标题窗口计算收益。《1943》补测约 45.19fps，但后续截图仍为关卡说明/过场，未取得稳定的实战窗口，不作为战斗性能结论。原始记录分别保存在 `toads-gameplay`、`1943-gameplay` 子目录。

最终候选包的九组初次采样窗口均确认 `sound=1`，各窗口 `audio_drop=0`。旧版《1943》的同协议窗口仍有累计 75 个采样丢弃。音频重试改动另有“主机刚恢复接收”“仍阻塞”“写入失败”和正常路径测试；不以队列统计代替主观听感验收。

## 防回归检查

这些检查用于保证性能改动没有改变模拟结果，并非本轮的主要兼容性验收：

- 6502 原解释器与优化路径 **1,042,516** 组用例签名一致：`130d9091`；包含部分迭代、标志、DMA、跨页、读处理器、银行切换、中断、解除映射及独立零页指针；ASan/UBSan 通过。
- PPU **6,291,456** 个像素行、**30,721** 个背景区间对照通过；Mapper 241 的 **2,048** 次合成银行写入测试通过，二者也通过 ASan/UBSan。
- 用户库 93 个游戏文件中 91 个能在原生内核完成固定输入测试；本轮优化前后这 91 个游戏的 CPU/RAM/PPU/视频/PCM 签名一致。原来可加载的 90 个也与 0.1.32 一致。另 8 个代表游戏每帧绘制的对照一致。不能把原生加载结果当成 91 个游戏的实机性能验收。完整清单另存 [library.md](nes-library-20261021/library.md)。
- 最终候选包的桌面 AOT 加载九款代表 ROM。重装机兵静态标题的 **56,832/56,832** 个有效 RGB565 像素与 FCEUX 相同；寻秦记彩色标题 **61,440/61,440** 像素相同。属于同调色板数字颜色验证，不是 LCD 光学校准。
- 前端音频与系统 i18n 测试通过。测试构建显式保留断言，避免 Release 下 `NDEBUG` 把检查消除。

Mapper 241 的寄存器行为参考 [Mesen Mapper241](https://github.com/SourMesen/Mesen/blob/master/Core/Mapper241.h)。源码仍保留 Nofrendo/Retro-Go 原许可证与本地修改登记。
