# 固定 SD 系统字体

GameKit 启动时明确选择已挂载的 SD 卷，系统字体使用卷内固定目录
`/PXA/system/fonts/`，无需用户选择目录。其他板卡默认继续使用内部字体；板卡可在
挂载完成、字体对象创建之前调用 `pxa_esp_system_font_prepare()`。桌面、Guest UI
语义字体和系统输入法统一使用 `pxa_esp_system_font_path()` 返回的启动期路径。

迁移仅识别当前工厂字体 `noto_sans_cjk_common.ttf`，大小 2,777,480 字节，SHA-256
为 `121cb206d826af5259cfb78418defde651a9daa80fa1d7d51de3eea716c934a4`。
更换工厂字体时须同时更新原生资源身份。不同的内部字体和同名 SD 文件不会被自动覆盖。

首次启动先验证内部副本，使用 4KiB 缓冲复制到 SD 临时文件，完成 `fflush`、`fsync`
和关闭后再发布文件；重新打开并验证完整哈希，复制 NOTICE 与 OFL 许可证后选择 SD
路径。GameKit 允许此时删除已验证的内部工厂字体，回收约 2.65MiB。应用、游戏资源、
分区表和其他系统文件不参与这次迁移。复制或发布失败保留内部副本。

以后每次启动重新验证 SD 字体。缺卡、损坏或未知同名字体不会被当成已验证资源。
内部字体仍存在时可继续使用；两者都不可用时使用固件已有的内置字形回退，中文覆盖
会减少。此处没有热拔卡保证，也不宣称 FAT 能保证任意掉电下的持久性。

普通 PXADB 写入禁止固定系统目录及其祖先的破坏操作，比较时处理 FAT 大小写，
并拒绝尾随点、空格和短文件名别名。Guest 的 SD 授权仍为只读。

`firmware/components/pxa/tests/test_system_font.py` 在 ASan/UBSan 下执行实际迁移源码，
覆盖相同文件、SD 单副本重启、损坏哈希、保留内部副本、同步/发布失败、缺卡和自定义
字体保护。原生路径策略另有边界测试。

2026-10-19 已在 GameKit / ESP32-S31 验证首次迁移：SD 文件大小与完整哈希
一致，内部字体副本已回收，中文桌面正常，原有 6 个应用记录保留，内部空闲
空间为 6,373,376 字节。只刷写应用固件，分区表与原设备备份一致。测试固件
SHA-256 为 `62dbcfc50e3a39af983d70e2972251775a9e21916ab582dce3b49cbf141e9ac3`。
此镜像含工作区原有的未提交图像适配代码，不能把这一提交当作该镜像的完整可重现版本。

这项实现只处理字体的位置。应用代码和私有存档仍在现有内部存储；整个应用安装到
SD、没有 Flash 文件分区的 SystemRoot 启动方案仍见
[完整存储设计](pxa-storage-layout.zh-CN.md)，不能用字体迁移代替其验收。
