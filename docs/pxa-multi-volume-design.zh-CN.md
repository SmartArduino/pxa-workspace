# PXA 多卷存储与访问接口

Host 按已挂载文件系统管理卷，应用按能力句柄访问资源。物理设备、分区、挂载路径、应用身份和目录授权彼此独立。整应用固定布局与安装流程见[存储布局](pxa-storage-layout.zh-CN.md)。

## Host 卷接口

`firmware/components/pxa/include/pxa/pxa_esp_storage.h` 是板驱动与 Host 的接入边界；核心模型位于 libpxa 的 `volume.h`、`install_plan.h`、`install_record.h`。

板驱动先挂载文件系统，再调用 `pxa_esp_storage_register_volume()`，提供原生路径、设备/分区身份、名称、读写能力、最大文件大小、分配单位及容量查询回调。FAT 可使用 `pxa_esp_storage_register_fat()`。不能将同一物理设备上的不同分区注册为同一身份，也不能把枚举顺序作为身份。

ESP 的全局 VFS 表和 LittleFS 实例数也要覆盖并发会话：商店本身可能使用私有镜像，安装器同时准备另一个镜像。公共默认值为 `CONFIG_VFS_MAX_COUNT=20`、`CONFIG_LITTLEFS_MAX_PARTITIONS=10`；已有本地 sdkconfig 需要合并这些配置。表容量只预留指针，实例及文件系统缓冲按需分配。挂载资源不足返回资源限制错误，不重格式化已完成的私有镜像。

每卷 `/PXA/volume.{0,1}.pxv` 保存持久 UUID。已有完整描述的满卷可只读发现；描述冲突、克隆身份或不可恢复损坏会被隔离，不重新分配 UUID 掩盖原数据。只读无描述介质需要板提供稳定文件系统身份。

| 标识 | 用途 |
| --- | --- |
| VolumeId | 持久卷身份，可写入本地安装记录 |
| mount_epoch | 本次挂载的易失标识；句柄、计划及 I/O 使用原 epoch |
| InstallID | 一次安装及其私有状态身份；归档重装保留，卸载重装改变 |
| publisher root + App ID | 签名应用身份，与位置及显示名称无关 |

挂载路径只用于本次 Host 路径解析。安装记录与持久授权使用卷 UUID、InstallID、签名身份和数据代际；同一卷从 `/pxa/sdcard` 改挂到 `/pxa` 时，保留原安装记录和授权，重新发现位置并签发本次挂载的句柄。旧 epoch 或旧路径不能复用。

`resolve_volume()` 按最长匹配挂载路径解析，包括私有别名；子卷失效时拒绝访问，不回落到父卷。`usage()` 提供不触发文件系统扫描的缓存容量概览，不计重复私有挂载。实际安装必须通过刷新后的计划与预留进行准入。

## 生命周期与并发

操作 owner 保留精确挂载实例，文件、代码和私有后端关闭后才释放。卷进入 draining 状态后立即拒绝新访问；仍有引用时 unregister 返回 BUSY，板驱动不能提前物理卸载。

卷清单锁只保护有界内存状态，不包住大文件读写。安装计划是不可复制的 owner 对象；两个目标卷的空间预留要么全部成功，要么回滚已预留部分。一个卷失去连接后，释放计划仍要释放其他存活卷的预留。

应用更新、清除数据、卸载与启动由 Host 的安装事务协调。启动共享一个私有存储会话给 FS、KV 和权限；失败卸载保留 owner 供重试，不能释放仍被文件系统回调使用的内存。热插拔硬件事件、取消有界 I/O、停止依赖者和字体回收需要板及系统生命周期配合；注册 API 本身不等于完成了热插拔支持。

系统字体通过 `pxa_esp_font_source.h` 的原生 owner 接口固定其挂载实例：先在已注册卷上 acquire，再把 `pxa_esp_font_source_path()` 返回的借用名称交给 FreeType。该名称包含原 epoch，应作为字体名称使用。owner 和各字体流分别持有卷引用；流按小块读取并检查原挂载是否仍可用。字体源只保留少量路径及流状态，大文件保持按需读取。

销毁相关字体和 FreeType 缓存后才能 release 字体源，再尝试注销卷。draining 会阻止继续读取和创建字体；同一路径重挂后需要重新 acquire，不能把旧字体源复用到新 epoch。系统、Host 和输入法的现有字号缓存共享这一生命周期；运行中的系统资源卷切换仍需要调用方先完成字体消费者的回收。

## Guest ABI 与 SDK

Guest 不接收原生路径、块设备指针或可伪造的安装卷句柄。选择安装位置属于系统确认框，商店只发送制品票据、身份、大小和摘要。

| 需求 | 接口 |
| --- | --- |
| 私有文件读写 | FS，Service 5；Host 自动路由到本次安装的私有后端 |
| 私有设置 KV | Storage，Service 6；与同一安装会话绑定 |
| 包内只读资源 | Assets，Service 21；按已验证包读取 |
| 自动游戏媒体根 | FS app-media-root，OPEN_ROOT kind 5；C `pxa_fs_request_app_media()`，C++ `fs.app_media()` |
| 用户主动选择其他目录 | FS 授权目录根；C `pxa_fs_roots.h`，C++ `Directory` / `DirectoryGrant` |
| 商店安装与离线缓存 | Store Installer，Service 20；Host 验证签名、确认卷、管理暂存和本地提交 |

授权目录首版只读。应用保存并重新兑换的是授权标识，不是永久有效的原生路径；根和打开文件绑定原挂载 epoch。持久授权保存在私有后端并认证绑定安装身份，介质重挂不能让旧文件句柄读取一张新卡。

可授权目录不能穿越嵌套卷、符号链接或受保护的 `/PXA/apps`、`/PXA/system`、`/PXA/cache` 和保留旧版状态根。大小写不敏感卷也不能通过大小写变化绕过保护。

同步 READ_AT 在 Host 的文件上下文上进行有界分块读取，不依赖可变的全局当前目录或媒体卷。当前游戏媒体可自动绑定，也可由明确授权的目录句柄提供；不要求用户在每次启动时定位资源。

## 安装与调试

原生安装协调器使用卷几何生成计划、预留空间，并把代码、私有状态及认证安装记录提交到目标卷。FAT 私有镜像提供与原生私有目录一致的语义。全量代码验证在启动及安装中执行；应用清单显示只读取有界元数据并核对认证摘要，不为刷新桌面反复扫描所有大文件。

私有文件系统初始化的容量扫描和目录清理使用迭代遍历，栈与打开目录数不随目录深度增长。扫描临时复用初始化阶段尚未使用的句柄表；调用方始终通过工作区查询接口取得所需大小。私有路径仍受 Service 5 的 255 字节及 4096 个条目限制，清理路径受 Host 的 1024 字节上限约束。ESP 的无链接 FAT/LittleFS 可一次解析完整相对路径，由 VFS 适配器校验挂载代次和卷边界；支持链接的 POSIX 平台仍逐级禁止跟随链接。长时间扫描、清理和迁移复制在文件操作之间按耗时让出 CPU，使空闲任务可以运行，不另建工作任务。代码与资源包的签名清单统一限制为 16 KiB，在按清单大小分配内存之前拒绝超限输入。

PXADB 的 `VOLUMES` 显示已注册卷和当前 epoch。`PACKAGE install-volume <epoch> <source>` 显式选择安装卷；epoch 0 使用默认放置策略，已有新布局应用保留原卷。PXADB 路径是开发工具的 Host 路径，不授予 Guest 相同访问权。

只有已注册卷才参与选择，不推断“第一张 SD 卡”。单卷、多个分区、多个 Flash、Flash+SD 和无主文件分区都通过相同模型接入；GameKit 的启动拓扑与固定路径规则见布局文档。

## 商店资源交付与后续边界

签名资源包使用流式打包、SDK 精确清单策略、原生不可变代际安装和运行时资源卷绑定。服务端先接收资源，再接收引用它的应用代码；两者随代码版本审核，使用同一已审核制品的限时下载凭证交付。

Store Installer 0.8 的原生确认界面分别选择“应用与数据”和“资源”所在卷，默认尽量完整安装到同一位置。Host 在下载前验证两份签名元数据并联合预留空间；应用与资源分卷时，任何一卷不足都不保留另一卷的部分预留。同卷时按资源安装、应用与私有状态准备两个阶段的最大占用预留，资源传输副本在应用准备前删除。资源完整验证通过后才提交应用记录；不可变资源代际可以复用。

Service 20 的能力查询区分资源联合安装、卷选择和资源离线缓存。当前提供前两项；仅下载资源组合包尚不支持。已有代码缓存可以复用本机已准备的精确资源代际。新版商店确认 Host 能力后使用 `*-pxa-0.5.0` Profile，旧 Host 继续使用 0.4.0，避免向旧固件交付 Manifest 0.8。

新布局应用可在原生设置中选择目标卷，移动应用与私有数据；Host 还提供目标卷继续迁移和启动自动恢复，保留安装身份、私有数据和重新签封的授权。确认使用完整源记录及原挂载实例，预览不预留空间或创建迁移目录，取消不改变安装。系统持有迁移任务及进度界面，复制复用已有运行时任务；转移凭据、源目录交接和目标隔离见[布局与迁移协议](pxa-storage-layout.zh-CN.md)。旧布局应用先在当前原生卷执行明确的存储升级，保留手工资源的实际卷并原地收拢其固定目录、私有文件、KV 和权限，然后使用同一跨卷移动入口。旧兼容记录的清理失败不成为新安装的启动条件。归档应用通过同一入口移动保留的私有状态和认证记录，保持不可启动状态，重装时重新验证代码与资源。无所属安装的资源迁移、资源副本回收，以及运行中系统资源卷切换和完整热插拔恢复仍有边界。
