# AOT 分段加载与可选解释执行验收（2026-10-15）

普通 AOT 已改为从可寻址文件读取器加载，TEXT 直接进入最终可执行 PSRAM。
Flash 文件系统、SD/FAT 和桌面文件共享接口；不要求 mmap 文件，不实现 XIP。
解释执行保留为显式的 Wasm 包选择。Guest ABI、普通 AOT 格式及应用机器码不变。

大 AOT 的启动峰值下降；稳态代码仍完整驻留。此功能不做运行时分页，不提高
游戏逐帧执行速度，也不会把 AOT-only 包自动切换为解释执行。

## 实现与采用原因

| 改动 | 原因与收益 | 内存及验证 |
| --- | --- | --- |
| `open_artifact`＋有长度的 `read_at`／`close` | 同一接口支持已挂载 Flash／SD，允许短读，打开一次 | FD 编码为 context，不为读取器分配堆对象；加载后关闭，执行阶段无存储回调 |
| 标准六段预检＋TEXT 直接读入最终映射 | 去掉整文件源缓冲与 TEXT 复制的重叠 | 单次请求 ≤16 KiB，直接写目标，没有 16 KiB 中转缓存；真机阅读器峰值降低 |
| WAMR 预加载段所有权补丁 | 提前复制初始数据与字符串，设置版本，正确释放部分失败的 TEXT | 成功／失败都消费 TEXT；错误注入、源覆写后运行及映射回收测试通过 |
| 读取回调使用 tagged union | 保留旧嵌入接口，不为新回调增加固定指针 | S3 Engine 176 B、Entry 368 B，修改前后相同 |
| 自定义段安全回退 | 自定义段可能借用源数据，不能盲目提前释放 | 含自定义段仍用完整源缓冲；原有行为及测试保留 |
| 显式 Wasm 模式 | 小型应用可比较解释器与 AOT 的实际取舍 | Wasm 仍保留源缓冲和解释结构；模拟器及 S3 交互通过 |
| 构建目录补丁 overlay | 桌面／ESP 共用加载契约，避免改脏 pinned WAMR | Git 子模块和不可变 Host SDK 归档两条校验路径均通过 |

涉及 SDK `libpxa/adapters/wamr`、`cmake/PxaWamrLoader.cmake`、桌面
`product_runner.c` 以及固件 `pxa_esp_host.c`。完整接入和边界见
[SDK 说明](../../deps/pxa-system/docs/zh-CN/aot-loading.md)。旧的 `read_artifact`
回调仍可用；生产 Host 已改用读取器。配置静态工作区的外部嵌入方仍需按说明
使用现有按需分配器，不能仅换回调就期待静态预留自动消失。

## 设备、基线和口径

- pai-touch，ESP32-S3，296×240；`/dev/ttyACM1`，2,000,000 baud；
  设备序列号 `28:84:85:63:b7:78`。本轮实际连接设备不是历史记录中的 ACM2。
- 可计数 SRAM 320,699 B，PSRAM 8,358,524 B。仅更新实际 OTA 应用分区；
  不覆盖救援镜像、分区表或数据分区。测试固件使用已存在的 `assets` 挂载，禁止格式化。
- 同一份测试固件用 test-only linker wrapper 切换两种普通 AOT 加载方式。
  每应用预热，随后两轮 B/S/S/B，每种方式各四次，共 32 个启动窗口；另有八次
  对公开对照脚本的真机复验。标记切换代码不在正式构建中。
- 表中启动峰值为 `total - MEMORY START/STOP 窗口内最低 free`，不是开机历史峰值。
  稳态取每次五个运行样本的中位数，再对四次启动取中位数。截图和输入不进入该窗口。
- 全系统数据包括系统 UI、资源和调度产生的占用；WAMR 的独立计数另列。
  `active_ms` 包含串口和轮询，不作为加载耗时或首帧延迟结论。

设备原产品固件的资源线程曾在进入 AOT 之前分配失败，因此没有把它与 standalone
测试固件的不同系统负载当作前后性能对照。早期分两份固件的试验也不作为下表依据；
最终使用同固件交替测量，并保留未改变加载方式的 Wasm 对照。

## 真机内存

单位 B，中位数；完整样本与范围见 [summary.json](aot-stream-20261015/summary.json)
和 [原始堆响应](aot-stream-20261015/heap-abba.json)。

| 应用 | 整文件 PSRAM 启动峰值 | 分段 PSRAM 启动峰值 | 整文件／分段 PSRAM 稳态 |
| --- | ---: | ---: | ---: |
| 手势示例 AOT（149,388 B） | 2,077,172 | 2,077,212 | 1,823,808 / 1,823,810 |
| 同示例 Wasm（69,268 B） | 1,915,204 | 1,915,198 | 1,808,974 / 1,809,018 |
| 小说阅读器 AOT（1,434,776 B） | 4,511,086 | 3,644,802 | 3,143,116 / 3,143,094 |
| Jump Jump 3D AOT（550,096 B） | 3,242,412 | 3,242,474 | 2,762,694 / 2,762,722 |

阅读器整机 PSRAM 峰值减少 **866,284 B（约 846 KiB，19.2%）**。
小应用与游戏的整机峰值基本相同，不能将源缓冲大小直接当作整机节省量。
几十字节的差值在样本波动范围内，不能解读为稳态占用改善或回退。

| 应用 | 整文件／分段 SRAM 启动峰值 | SRAM 稳态（两者相同） |
| --- | ---: | ---: |
| 手势 AOT | 268,252 / 268,282 | 264,868 |
| 手势 Wasm | 268,252 / 268,252 | 264,820 |
| 小说阅读器 | 269,004 / 269,004 | 264,868 |
| Jump Jump 3D | 307,884 / 310,960 | 303,488 |

**待核查：游戏启动窗口的 SRAM 峰值增加 3,076 B。** 此差异在四次重复中均出现，
不能忽略或宣称整机所有峰值均不增长。读取器没有新增固定 SRAM 缓存，WAMR
按需分配仍使用 PSRAM，稳态 SRAM 完全一致；目前未用分配调用栈证明这 3 KiB
的来源，启动阶段音频／系统任务的分配重叠只能作为待验证假设。本轮保留记录，
不将“固定开销不增加”扩大为“所有系统调度下瞬时峰值不增加”。

WAMR 独立稳态记录在两种方式下完全一致：

| 应用 | Runtime 元数据 | Guest 线性内存 | 可执行映射 | 保留 Artifact |
| --- | ---: | ---: | ---: | ---: |
| 手势 AOT | 29,487 | 131,072 | 196,608 | 0 |
| 手势 Wasm | 134,551 | 131,072 | 0 | 69,268 |
| 小说阅读器 | 56,912 | 131,072 | 1,376,256 | 0 |
| Jump Jump 3D | 37,838 | 131,072 | 524,288 | 0 |

I-Bus／D-Bus 是同一物理映射的两个地址，不重复相加。卸载后线性内存和 Artifact
归零，运行时保留 416 B 全局基线。新路径的非 TEXT 临时段计入 Runtime 峰值，
所以单看 Runtime 峰值可能变大，必须同时核对已去掉的 Artifact 源缓冲。
游戏帧缓冲 426,240 B、mailbox 49,152 B；PERF 记录另用 2,176 B，未由加载器改变。
本轮没有新增深度缓冲、命令队列或逐帧缓存。

## 原生受控内存与错误清理

Linux ASan／UBSan 测试对同一模块增加 2 MiB TEXT 尾部，再比较两条路径：

| 请求分配字节，含全局 Runtime 基线 | 整文件 | 分段 |
| --- | ---: | ---: |
| 峰值 | 4,198,232 | 2,100,728 |
| 加载后稳态 | 2,100,272 | 2,100,272 |

这是分配请求与可执行映射的计数，**不是 Linux RSS，也不是真机物理堆数据**。
它隔离了加载器，证明去掉整文件与 TEXT 复制的重叠；真机收益仍以上表为准。

测试覆盖：20 次源数据覆写后的运行、13 个读取调用失败点、616 个截断长度、
八种尾部附加数据、30 个分配失败位置、20 次接管 TEXT 后的 FUNCTION 解析失败，
以及 XIP 拒绝。Linux 追踪 executable mmap／munmap，失败后映射及 Runtime
分配均回到基线。实际组件流程另测短读文件后端、Wasm、AOT、自定义段、停止及
失败导入，并核对 open／close 次数。纯解释器构建也验证了 AOT 禁用 stub。

同一签名 Jump Jump 3D 0.1.5 包、相同默认种子 `0x9e3779b9`、296×240，
两种加载方式各两轮 idle／charge，预热 1 秒、测量窗口 3 秒。使用面板完成间隔，
不使用应用提交 FPS。动态蓄力后的结束画面可能停止刷新，所以另列整个窗口的帧率。

| 场景／指标 | 整文件 | 分段 |
| --- | ---: | ---: |
| idle 显示 FPS（两轮均值） | 28.79 | 28.58 |
| idle 全窗口 FPS | 28.29 | 27.97 |
| idle Host 光栅化中位数 | 19.976 ms | 20.181 ms |

| charge 全窗口 FPS | 9.82 | 9.66 |

未观察到明确帧率回退，也没有足够样本证明帧率提升。UART 注入蓄力的实际时长仍受

  每轮包括启动、输入、HOME 后恢复及卸载；最后源码版本又各验证一轮。

## 恢复与限制

六个本轮测试应用及其数据已清理，恢复原应用固件 **1.3.1** 和原配置。
刷写校验通过；分区表与配置回读均逐字节等于测试前备份。原救援镜像和资产分区
未刷写或格式化。构建目录恢复正常 pai-touch SDKCONFIG，去掉 test wrapper 后
重新构建完成；未将 standalone 的默认分区布局写入原产品设备。

尚未验证物理 SD 卡：接口与文件后端可以用于已挂载 SD/FAT，短读／错误行为已有
自动化覆盖，但这不等于验证了 SD 驱动、挂载、拔卡或商城安装至 SD。macOS 的
MAP_JIT 写保护分支未做实机验证。Wasm 真机验收限于交互示例，不代表游戏解释
执行也能保持 AOT 帧率。游戏 SRAM 启动峰值的 3 KiB 差异仍需单独归因。
