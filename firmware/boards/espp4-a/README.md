# ESPP4-A

SmartArduino ESPP4-A / ESP32-P4 DevKit v1.1 的 PXA 板级适配。
硬件参数和 ST7102 初始化表来自
[SmartArduino/ESPP4-A](https://github.com/SmartArduino/ESPP4-A/tree/1e981d9f159a1afb30bd5e41b0137344ce3916a6)。

400 MHz配置在创建系统main任务前临时切到200 MHz，让调度器完成main与idle任务栈初始化；
板级初始化开始时恢复配置频率，再初始化外设。启动日志输出实际运行频率，运行阶段仍为400 MHz。
该板的RTOS创建适配只在调度器尚未启动、任务名为main时调整频率；保留内存保护和完整栈水位填充。
这是针对早期内部SRAM写入异常的板级启动处理，不降低相机和应用运行时的CPU频率。

默认界面显示密度为 240 DPI，使文字、间距和控件相对 200 DPI 放大约 20%，
便于在这块屏幕上阅读。应用通过显示环境获取密度；像素画布仍按应用自己的缩放策略显示。
二级缓存使用 128 KiB，为无线 DMA、TLS 和应用安装线程保留足够的内部 RAM。
改变缓存大小时需同时更新 bootloader 与应用固件；分区表和用户数据无需重写。

显示在板级完成合成。原生方向的桌面和系统控件使用 LVGL DIRECT 模式，
只重绘失效矩形，由 LVGL 同步两个 DSI DMA 缓冲中的已更新区域。
一次刷新含多个矩形时，仅在最后一个矩形完成后提交屏幕。
帧率浮层的小矩形也纳入失效区域，显示、隐藏和缓冲同步均不会留下旧数字。
应用 Surface 可见或切换到非零方向时恢复 FULL 模式：先重绘完整原生 UI，
再合成 PXA Surface 和透明层，避免复用含有旧应用像素的背景。
切换前排空待完成的 DMA 帧，返回桌面的第一帧完整重绘后再恢复局部更新。
首个应用 Surface 在原生绘制过程中才到达时，推迟到下一次完整合成再显示。
`PXA_ESPP4_NATIVE_UI_DIRECT=OFF` 可用于完整重绘对照，不增加第三块整屏缓冲。
`bash firmware/boards/espp4-a/tests/test_ui_render.sh` 使用真实 LVGL 对比完整
重绘与局部重绘的逐像素结果，覆盖多个失效矩形、浮层开关及应用/桌面切换。
DMA 在帧边界切换缓冲后允许
LVGL 绘制下一帧；帧率统计和截图另等完整扫描结束，避免把提交次数当成显示帧率。
RGB565 Surface 按可见跨度逐行复制，2 倍／4 倍放大按源行展开并复用重复行。
存在系统不透明遮挡区时仍使用逐行路径，只复用应用像素，不复制状态栏、导航条
等原生 UI；透明层在行复用后单独合成，保留每个物理像素的透明度。
ARGB 同尺寸画面按行合成，按遮挡区和透明度平面跳过不可见跨度；其他缩放
与复杂混合保留通用合成。
Window 0.5 支持应用动态选择横屏、竖屏和 0°/90°/180°/270°。本板原生方向为
480×854；90°/270° 的逻辑画面为 854×480。非零角度首次分配一个约 801 KiB
的 PSRAM 缓冲，先按逻辑方向合成，再使用 P4 PPA 的 RGB565 硬件旋转写入
DSI DMA 缓冲。旋转事务完成后才提交显示；缓冲按 L2 缓存行对齐，由 IDF
驱动同步 CPU 缓存与 DMA。硬件初始化或事务返回错误时退回软件旋转。
PPA 只旋转，不进行插值缩放，保留像素画布的整数缩放效果。
旋转画面在首次 DMA EOF 完成缓冲交接后复用退出扫描的缓冲，让下一帧合成、
旋转与当前帧扫描并行；完整帧统计仍等待随后一次 EOF。截图和切换方向会先
排空待完成帧，避免读取正在复用的缓冲。此流水线不额外分配整屏缓冲。
RGB565 游戏没有遮挡区、可见透明层或系统弹窗时，可跳过不必要的 LVGL
背景重绘。铺满屏幕的画布直接合成；带黑边的画布须先完整检查一次 LVGL 绘制
结果为纯色背景，随后只填充画布外的留边，再合成应用画面，不增加背景帧缓冲。
留边按当前画布的位置、缩放与裁剪范围重算，移动或缩小画布时也会清除旧像素。
通过公开的 LVGL 区域失效事件记录绘制版本；页面、系统栏或弹窗变化后，必须
先完成正常 LVGL 绘制才能恢复快速路径。原生方向直接写入退出扫描的 DMA
缓冲，交接完成后通过公开缓冲 API 将 LVGL 下一绘制目标重绑到已释放的缓冲。
旋转方向保留逻辑缓冲与 PPA。Host 的前台、解锁、恢复屏障、完整扫描统计和
截图等待规则保持一致；ARGB、非纯色背景、系统界面和缺失快照均走正常合成。
LVGL 任务和公共定时器继续运行；快速路径只省去重复的背景绘制，不暂停输入、
输入法、系统栏或息屏处理。桌面和设置页的旧控件树由系统框架在切页时销毁。
回到 0° 恢复原有直接绘制路径。物理触摸同步反变换，PXADB 输入及截图使用当前逻辑坐标。
退回桌面恢复系统方向，重新进入应用恢复该应用的方向请求。

GameRender 的 PSRAM 分配和缓存写回按配置的 L2 缓存行大小对齐，支持本板
128 字节缓存行；帧尾保留完整缓存行，避免写回相邻对象。
DSI／DW-GDMA 中断及帧完成回调驻留 IRAM，回调上下文与静态信号量驻留
内部 DRAM，Flash 存档暂停缓存时仍能继续扫描。串口每 10 秒输出扫描次数、
超时扫描间隔及 Surface 获取失败计数，并输出平均合成、旋转耗时和硬件／软件
旋转次数；背光日志仅在状态变化时输出。
PXA Surface、系统透明层、
锁屏、物理触摸优先级和 PXADB 输入都在同一个板级显示锁下协调。
触摸支持五个独立触点，按 ST7123 原始报告的固定槽保留触点身份；抬起一指
不会移动其余触点的 ID。五个 LVGL pointer 同时供原生触屏和 PXADB 多指测试
使用，真实触摸优先接管。读取短暂失败保留触点，连续失败 150 ms 后取消全部
触点并等待松手，防止误点击或卡住的拖动；唤醒、锁屏与系统按键同样取消旧输入。
GPIO52 中断唤醒输入任务；按住或中断线持续拉低时保留 16 ms 轮询兜底。
首次收到真实中断之前也维持此轮询，确认中断工作后空闲检查降为 500 ms。
读取失败按 10～160 ms 退避，避免连续错误重试占用总线。每 10 秒的诊断还包括
触摸中断、读取与错误次数，以及输入、LVGL 定时器耗时和直接呈现帧数；这些
耗时包含任务等待与抢占，不能直接换算为 CPU 占用率。
启动时 bootloader 先将 GPIO24 拉低；PXA Logo 完整扫描并稳定 100 ms 后才
开启背光，Logo 至少显示 1.2 s，再由完整桌面帧接替。首次更新启动策略需
使用 `flash` 同时更新 bootloader，后续普通应用固件更新可用 `app-flash`。
全屏应用请求永久隐藏系统栏时，系统仍保留底部边缘手势。三按键模式下从最底边
上滑可临时唤出导航，中间主页键返回桌面；右侧最近任务可划掉卡片结束应用。
手势模式保持底部上滑回桌面的操作。应用无法通过隐藏系统栏屏蔽此入口。

音频输出由 PXA 混音工作线程写入 I2S；麦克风 RX 仅在授权捕获资源打开期间启用。
ES8311 使用 BCLK 派生时钟，NS4150 由 3.3 V 供电且控制脚通过电阻固定使能，
没有需要软件拉高的功放 GPIO。扬声器需接在板载 J1 接口；初始化和输出错误
通过 `espp4_audio` 日志报告。维护时可用 `-DPXA_ESPP4_AUDIO_SELFTEST=ON`
构建开机短音与 DAC 数字回采检查，普通固件默认关闭；数字回采通过仍须听音
确认扬声器端的实际输出。
Audio 0.16 的缓冲 PCM 模式可由语音应用显式请求：默认会话仍为 4 个 20 ms 包，
缓冲会话最多 24 个包（480 ms），预存 400 ms 或启动期限到达后播放。
队列排空后下一句重新预存，打断会清空队列并重置预存状态。ESPP4-A 将扩大的
约 139 KiB 混音工作区放在受预算管理的 PSRAM；其他板型保留默认包池大小。
无 SD 卡时继续启动，挂载失败不会格式化存储卡。
GC4023 使用 CSI RAW10、ISP 去马赛克与 Gamma、自动曝光及灰度世界白平衡，
通过 P4 硬件 JPEG 编码提供以下档位，原有档位 ID 保持稳定：

| ID | 拍摄尺寸 | JPEG 质量 | 用途 |
| --- | --- | --- | --- |
| 9 | 320×240 | 75 | 快速档，中央 4:3 裁切，原生像素预览 |
| 1 | 320×180 | 75 | 16:9 宽屏预览与录像 |
| 2 | 640×360 | 80 | 标准画质 |
| 3 | 160×90 | 60 | 减少 JPEG 数据量 |
| 4 | 480×270 | 78 | 屏幕宽度档 |
| 5 | 800×450 | 80 | 增加细节 |
| 6 | 960×540 | 78 | 中高分辨率 |
| 7 | 1280×720 | 70 | 720p |
| 8 | 1920×1080 | 60 | Host 默认 1080p 流畅，直接使用原生 CSI 帧编码 |
| 10 | 1920×1080 | 82 | 相机 App 照片默认 1080p 高清，需 peripherals 0.8 |
| 11 | 240×320 | 75 | 竖屏 4:3，对应横屏 ID 9 |
| 12 | 180×320 | 75 | 竖屏 16:9，对应横屏 ID 1 |
| 13 | 270×480 | 78 | 竖屏屏幕宽度档，对应横屏 ID 4 |
| 14 | 720×1280 | 70 | 竖屏 720p，对应横屏 ID 7 |
| 15 | 1080×1920 | 60 | 竖屏 1080p 流畅，对应横屏 ID 8 |
| 16 | 1080×1920 | 82 | 竖屏 1080p 高清，对应横屏 ID 10 |

高清档的 JPEG 单帧上限为 1 MiB，其余档保持 256 KiB；复杂画面超过档位
上限时报告限制错误。旧客户端枚举不到高清档，默认回退到 1080p 流畅档。
传感器固定为 25 FPS，实际录像速度取决于 JPEG 编码、显示及存储。
1080p 使用 PPA 将 CSI 帧按 7/16 缩为 840×472（竖屏为 472×840），再复制到不可变 Core 预览图像，
在 480×854 屏幕上按原始像素居中显示，避免 CPU 遍历完整 1080p 帧与屏幕放大重采样。
较小的窗口按比例缩小，PPA 不可用时回退到 CPU 小预览。
JPEG 编码器直接写入 Host 中对齐到 128 字节的帧流缓冲，避免编码结果的额外复制。
竖屏档按顺时针 90° 旋转传感器画面，JPEG 与 MKV 保存实际竖屏尺寸。
原生竖屏使用 PPA 旋转到一个固定的 1080×1920 RGB565 DMA 缓冲，再做硬件
JPEG 编码；CSI 归还前已完成旋转，避免编码期间覆盖源图。PPA 故障时回退
CPU 变换，小尺寸竖屏合并缩放与旋转，不创建完整传感器尺寸的中间图像。
竖屏 1080p 比横屏额外需要约 4 MiB DMA 存储，分配失败会返回资源错误。
其他档位直接从 CSI 帧生成小预览，不分配拍摄尺寸的预览中间图像。
320×240、320×180 档的预览图像同时作为 JPEG 输入 DMA 的只读缓冲；
1080p 直接读取受持有保护的 CSI 帧，其余档位只为 JPEG 保留一次缩放。
编码为独立图像后提前归还 CSI 帧；Flash 写入等背压后丢弃超过 80 ms 的旧帧，
等待当前画面。录像的 JPEG 和预览复用同一帧。相机硬件仅在获得
`camera.jpeg` 权限后由相机工作线程启动，关闭后停止采集并释放 DMA 缓冲、
ISP、JPEG、LP-I2C 和 MCLK。摄像头不重新配置或释放显示共享的 MIPI LDO3。
两个固定 1080p CSI 缓冲与当前档位的编码缓冲为有界板级 DMA 内存；发布到
Core 的图像另受8 MiB外部资源预算约束。固定 CSI 双缓冲与缩放、预览缓冲分别
分配，避免录像、相册访问后的堆碎片要求一次连续分配约13 MiB。板级 DMA 与
Core 资源的合计用量仍须用实际 PSRAM 空闲值检查。CSI 和显示的 DMA 中断保持缓存暂停期间可用。
`camera.lf` 补齐当前 IDF 未纳入 IRAM 的 DW-GDMA 传输配置函数，确保相册
写入 Flash 时 CSI 中断可以继续交接缓冲；ISP 使用独立 160 MHz 时钟源。
普通内存 JPEG 通过板级完整图像解码入口复用 `esp_lv_decoder`，避免把其仅供
分片格式使用的区域回调应用于相册 JPEG。超过 640 像素边长时使用现有 JPEG
解码器的缩放输出，将显示工作缓冲限制为至多 512×512，保留磁盘文件的原始
分辨率。图像分配继续受既有预算约束。

TF 卡在无线模组完成共享 SDMMC 初始化后挂载，配置为四线 2.5 MHz、固定
3.3 V，不请求 1.8 V UHS 电压切换。接线与 DevKit v1.1 原理图一致；DAT0～3、
CMD 及检测脚有 51 kΩ 上拉，CLK 直接连接。上电前通过 GPIO4 关闭 Q1，
拉低数据/命令线协助放电，等待 2 秒后释放引脚并重新供电，避免卡片异常状态
跨主控复位保留。
卡初始化前将 GPIO39～44 的驱动强度设为级别 1。IDF 的最大驱动强度以及
更高的时钟在本板与当前 SDSC 卡组合上出现写入 CRC 错误或超时，因此不直接
沿用上游的 10 MHz。仍使用四线和多块 DMA；提高频率前需重新验证大文件写入、
回读校验与无线共存，不能用成功挂载或小文本读写作为稳定性依据。
`espp4_a_sd_bus.h` 的递归协议锁覆盖整段卡初始化、块读写及无线 CMD52/CMD53，
保留 CMD55/ACMD 和数据/状态命令序列的插槽所有权；不锁住 SDIO 中断等待。
每次块命令最多 16 KiB，保持在当前 IDF 默认四个 DMA 描述符的窗口内，
已满足 DMA 条件的缓冲不额外复制。写命令在原生控制器锁内等待 DAT0 忙状态
结束，超时及错误仍交给上层处理，不自动重试或格式化。
`PXA_ESPP4_SD_SINGLE_BLOCK` 只供排查多块命令问题，默认关闭。
当前持续 TF 写入仍可能触发触摸控制器 I2C NACK，之后读取持续失败，重启可
恢复。触摸退避只限制失败重试与总线占用，并未修复此问题；不能以文件回读
校验通过代替触摸与存储同时工作的验证。
开发构建可用 `-DPXA_ESPP4_SD_SELFTEST=ON`，在独立临时目录内写入并读回
4 MiB 加 37 字节，检查 CRC、文件尾及缓冲边界，报告原生 VFS 读写速度；
成功后删除自己创建的文件，失败时保留诊断文件。正式固件默认不包含该测试。
`tests/sd_probe_fw` 是独立 IDF 诊断程序，串口命令可比较总线宽度、频率、驱动强度
及传输块数，使用 POSIX 读写直接测试对齐的 DMA 缓冲。仅将其应用镜像写入
`0x10000`，测试结束后恢复 PXA 应用；不烧写诊断工程的分区表或引导程序。
挂载点为 `/pxa/sdcard`，使用 UTF-8 长文件名，支持直接安装相机应用，
其私有相册随应用保存在同一卷。相机应用支持 JPEG 拍照、MJPEG/Opus MKV
录像及相册回放；麦克风需要另行取得 `audio.capture/microphone` 权限。
本板每应用私有文件总配额为 16 MiB，照片和录像共享配额，且仍受卡片剩余
空间限制。挂载失败时不会格式化卡片，移除卡片前应先停止录像并退出相机。

## 构建与接入

使用提供 ESP32-P4 v3 支持的 ESP-IDF 6.1/6.2 环境，以及对应的 RISC-V 工具链。
板级 defaults 选择 newlib，以匹配厂商无线二进制 ABI。

```sh
tools/firmware.sh espp4-a build
tools/firmware.sh espp4-a flash --port /dev/ttyUSB0 --baud 2000000
tools/firmware.sh espp4-a monitor --port /dev/ttyUSB0 --baud 2000000
# 安装本固件后，原生 USB HS 口提供 PXADB：
python3 tools/pxadb/pxadb.py info --port /dev/ttyACM0 --baud 2000000
# UART-DEBUG 口也提供 PXADB：
python3 tools/pxadb/pxadb.py info --port /dev/ttyUSB0 --baud 2000000
tools/firmware.sh espp4-a app-flash --port /dev/ttyACM0
```

端口编号由主机分配，以上仅为示例；应按 USB 产品名和 MAC 序列号确认目标，
Linux 可使用 `/dev/serial/by-id/` 的稳定链接。CH340X 的 RTS / DTR 接到
EN / BOOT，串口保留 UART0 启动日志和硬件自动下载，运行期默认速率为 2000000。
控制台使用 `CONFIG_ESP_CONSOLE_UART_BAUDRATE`，PXADB 使用
`CONFIG_PXADB_UART_BAUD`；共享 UART0 时应保持一致。烧录速率由 esptool 独立协商。
需要较低速率时可将这两个配置同时改为 `1000000` 或 `115200`，重新构建固件，
并给主机工具传入相同的 `--baud`。已有构建目录需同步更新其 `sdkconfig`；
板级 defaults 不会覆盖旧配置。板载 CH340X 的额定上限为
[2 Mbps](https://www.wch.cn/products/CH340.html)，不将 3 Mbps 作为该接口的支持档位。
ROM 下载握手仍使用 115200，应用运行日志会切换到上述配置的速率。

原生 USB 默认运行 TinyUSB 高速 CDC，产品名为 `ESPP4-A`，序列号为本机
MAC；PXADB 的应用安装、文件、日志、输入和截图均使用该接口。CDC 的波特率
不决定 USB 总线速度。普通连接及关闭调试连接不会触发复位。

板级 `tools/usb_esptool.py` 已通过 `ESPTOOL_WRAPPER` 接入 IDF 烧录目标。
运行态使用 1200 波特率下的 DTR 下降沿请求下载；独立任务等待应用停止和存档，
退出 CDC，再经 IDF 完成双核、DMA、缓存与时钟清理后复位进入 ROM。主机按相同
MAC 等待 `ESP32-P4` ROM 重新枚举，并用 `no-reset` 连接，避免再次复位丢失下载模式。
已经处于 ROM 时直接连接；CH340、其他 USB 产品和离线镜像生成均保持原有行为。
首次安装其他厂商固件时，请先用 CH340 烧录；本适配不依赖其他固件响应下载请求。

默认同时启用原生 USB CDC 和 UART0 PXADB：主传输选择 USB CDC，
`CONFIG_PXADB_UART_SECONDARY=y` 保留 TX37/RX38 上的第二个会话。
两端独立握手、收发、订阅日志与解锁系统写入；同一设备的 MAC 相同。
上传和安装共用设备级写入占用锁，另一端的冲突操作返回 `transport_busy`，
不会因第二端连接或断开而删除第一端的上传。控制命令由同一任务执行，耗时操作
仍会串行等待。关闭 secondary 可只保留原生 USB；主传输改选 UART 则只运行 UART。
自适配板型需先确认原生 USB 接线及调试 UART 引脚，不能只照搬 VID/PID 或引脚号。

`factory` 应用分区为 7 MiB，`pxa_data` 从 `0x710000` 开始，占用剩余
`0x8f0000` 字节。固件烧录不覆盖该数据分区；已有数据挂载失败时保留原内容。
首次出厂接入可使用通用工厂配置生成带系统字体的 LittleFS 镜像：

```sh
tools/factory.sh image espp4-a --profile factory/profiles/generic.toml \
  --output local/artifacts/espp4-a/factory/pxa_data.bin
```

为新设备烧录此镜像到 `0x710000` 后重启。对已有设备，先备份数据，按
项目的 PXA 应用交付流程迁移；不要把工厂镜像当作日常应用安装方式。
后续使用 PXADB 安装独立的 `.pxa` 应用。设备目标是 `esp32-p4`，AOT
产物必须匹配此目标；不能安装 S3 或 S31 的专用机器码。
像素游戏应使用 `pxa build ./game --target esp32p4 --aot-only` 构建 P4 原生包。
仅提供通用 WASM 时会使用解释执行，安装兼容不代表具有原生包的帧率。
比较板卡性能时应固定游戏版本、场景和画布尺寸，并统计实际完成显示的帧。

P4 的 AOT ABI 与 S31 同为 `riscv32` / `ilp32f`，但机器码还必须匹配芯片
指令集。P4 v3 增加 Zba/Zbb/Zbs；通用 P4 包为兼容早期芯片不会启用它们。
在已经从实机确认版本的 v3 板上，可生成限定此版本的本地测试包：

```sh
python3 firmware/boards/espp4-a/tools/build-v3-app.py local/pxa-apps/duke3d \
  --chip-revision 3.2 --output local/artifacts/espp4-a-v3/duke3d
```

此工具复制一份本地 SDK 构建配置，保留 `esp32-p4` 目标、签名校验和
ILP32F ABI，仅增加 Zb 指令；不修改通用 SDK 配方。生成目录附带最低版本
要求，包本身仍使用通用目标标识，因此只能用于已核实的 v3+ 设备测试，
不能作为兼容所有 P4 的包发布到商城。

`PXA_ESPP4_PIXEL_ACCEL` 默认开启，使用两个 HP 核上的 PIE 指令加速 RGB565
填充及精确 2/4 倍最近邻展开。接入原生 LVGL 实色填充、GameRender 填充和
板级 Surface 放大；遮罩、混合、对齐不满足要求或未绑定核心的任务继续使用
原有实现。PPA 继续承担整屏旋转；其缩放使用插值，不能替代像素游戏的精确
最近邻展开。`PXA_ESPP4_PPA_FILL` 默认关闭，仅供比较大面积清屏使用。
开发构建可用 `-DPXA_ESPP4_PIXEL_SELFTEST=ON`，启动时分别在两个 HP 核
运行像素差分、边界检查及填充/展开微基准；正式固件默认不包含此测试。

`tests/display-probe` 提供不写存档的原生 GameRender 测试应用：四个色块与移动
标记持续重绘，点击切换四个方向。按应用签名流程构建为 `esp32p4` 包后，
可用 `tools/measure-device-display.py` 测量；`--install --keep-installed` 安装并
记录本轮测试包归属，之后使用相同的包和 `--ownership` 文件对比固件。
每次使用新的 `--output` 目录，日志、截图和结果统一放在 `local/artifacts/`。
最终一轮加 `--cleanup`，只移除本轮安装的测试应用并检查原有应用及版本仍在。
测试期间独占串口，关闭其他烧录和监视进程；截图及内存查询均在计时窗口外执行。

硬件旋转的整屏逐像素比对可在开发构建中通过
`-DPXA_ESPP4_ROTATION_SELFTEST=ON` 启用。首次进入非零方向时测试三种旋转，
比较 PPA 输出与软件参考实现，临时使用约 1.6 MiB PSRAM，完成后释放。
此检查默认关闭，正式固件不包含测试代码和临时缓冲。

## 无线与许可证

无线驱动随源码保存在 `vendor/p4_wireless/`，固定于上述上游提交并保持原样。
它支持 STA 或 SoftAP，不支持 APSTA。板级链接包装将共享配网页面申请的
APSTA 转为 AP；配网控制器先停止 STA，再启动 AP，因此不会并行运行两种模式。
日常联网可直接在系统 Wi-Fi 设置中扫描和连接。
`espp4_a_sdio.cc` 在 SDMMC 公共 API 边界为不满足当前 IDF DMA 对齐要求的
无线缓冲提供内部 DMA 暂存，保留原始地址、传输长度及错误返回，不修改厂商库。
板级 RTOS 包装将无线总线工作线程的最小栈设为 6 KiB，满足当前 IDF 的
SDMMC 调用深度。启动时暂留 40 KiB 连续 SRAM，串口服务初始化后交还给
PXA 运行时，避免外围设备分配将运行时线程所需的连续栈空间碎片化。

`p4_wireless` 采用厂商专用许可，只允许在 SmartArduino 或其授权分销商的
ESPP4-A 模组上使用和随产品原样分发。必须保留
`vendor/p4_wireless/LICENSE`，不得修改二进制或绕过模组授权。
ST7102 初始化表采用上游 Apache-2.0 许可，完整许可证保存在
`vendor/LICENSE.upstream`。newlib 和 GCC 运行库的归属声明保存在
`vendor/runtime-licenses/`；自动许可门禁固定审查通过的目标归档和许可证哈希。

GC4023 的 ESP32 适配保留 SmartArduino 的 Apache-2.0 许可，寄存器及增益表
核对自 OpenHisilicon 的 MIT 传感器库，保留 Shenshu 原始版权。OpenHisilicon
对传感器库和内核模块分别声明 MIT 与 GPL，固件只使用前者。固定来源、完整
许可及修改说明见 `vendor/gc4023/NOTICE`，不以无许可的 HiSpark 副本作为授权依据。
