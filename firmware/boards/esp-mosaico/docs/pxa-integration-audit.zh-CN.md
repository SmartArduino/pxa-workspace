### 输入所有权

`EspMosaicoInput` 保留原有两组固定容量队列和物理指针槽位，由 `touch_lock_`
串行访问。进入注入模式前释放已有 UI 手势，完整保留远程 DOWN/UP；取消与
所有权切换会清除未消费的旧样本，并使 LVGL 等待释放，避免把取消当作点击。
没有活动物理触点的报告不会结束注入；有效物理触摸接管后，后续 PXADB 取消
不会释放真实手指。通知 PXADB 的回调在离开锁后调用，避免取消回调重入死锁。

两个逻辑指针先于物理控制器创建，即使 CST92xx 探测失败，远程输入仍可使用。
现有输入任务仍会启动，电量采样也不依赖触摸芯片成功初始化。

### 电池采样

接入参考本地 micropixel 的 Mosaico 板级配置和 BQ27220 实现，并按
[TI BQ27220 技术参考手册](https://www.ti.com/lit/ug/sluubd4a/sluubd4a.pdf)
核对寄存器及 I2C 时序：地址 `0x55`，`0x08` 起连续读电压/状态/电流，
`0x2c` 读电量百分比；`BATTPRES` 为 bit 3，`FC` 为 bit 9。

每两秒采样一次，每个 I2C 操作超时为 2 ms；400 kHz 下两次访问电量计之间
保留 80 µs 间隔，满足手册第 5.3 节的至少 66 µs 要求。读操作在已有输入任务
中进行，10 ms 触摸轮询改用绝对周期，避免在每次 I2C 操作后再额外等待完整周期。
这不是最坏触摸延迟保证：总线争用、触摸驱动原有的 20 ms 超时和调度仍可能延迟。

UI 读取单个原子缓存，不访问 I2C。电压、百分比或状态异常时保留短期有效数据，
连续十秒无有效数据后失效；明确报告无电池时立即失效。正向电流超过 5 mA 且
未满充时显示充电。USB 插入且电池已经充满不等于“仍在充电”，因此不根据 USB
连接盲目点亮充电图标。

采样**不解封、不改电池容量、不写 gauge data flash**。百分比准确度依赖电量计
已有的电池配置和学习状态，本轮没有进行实际充放电校准。

### 电源操作

确认菜单操作或收到 PXADB 关机请求后，现有输入任务执行操作，UI 和 PXADB
线程立即返回，不新增电源任务或任务栈。重复请求合并，冲突请求不重复执行。
执行时关闭应用交互，尝试等待 Guest 保存/卸载，最多等待 1200 ms，随后留出
120 ms；超时会记录日志，仍继续用户已确认的重启或关机操作。

重启调用 `esp_restart()`。关机等待现有刷屏结束，关闭面板及功放，持续拉低
GPIO57 开漏输出请求 SAM8108 切断电源，不改变保存的音量/亮度。输入工作任务
未能创建时返回失败，不把未调度的操作报告为已执行。

修复了初始化电源渐变失败时删除尚未创建的 `te_ready_` 信号量的问题。

## 仍未暴露的硬件

| 硬件 | 当前限制 |
| --- | --- |
| BMI270 加速度计/陀螺仪、BMM150 磁力计 | 当前 ESP Host 的 Sensor 服务使用空 provider，descriptor 为零。需要新增可选 provider 注入及 Bosch 驱动，不能只在板卡注册一个假传感器。现有 ABI 有加速度/角速度单位，磁场单位及坐标约定还需补齐 |
| 震动与状态 LED | 当前 PXA 服务没有对应控制协议；GPIO8 的电机和仅部分版本存在的 LED 不能作为任意 GPIO 默认开放，需要独立可选能力和资源所有权 |
| ES8311 麦克风 | 当前 Audio 服务提供播放而非录音，板卡只创建 TX；需要录音服务与输入资源管理，未将输出初始化成功误报为已支持录音 |
| SPI NAND | 独立 SPI3 存储尚未接入当前 NOR LittleFS 挂载策略。需要 NAND 驱动/坏块与掉电策略、文件系统挂载点及迁移方案；本轮未探测后自动格式化它 |
| Light sleep | 尚需与 TE、QSPI、I2S、USB CDC、Wi-Fi 和 Host 任务联合管理；当前灭屏只关闭显示与应用交互，不宣称进入芯片睡眠 |

这些是需要新增协议或驱动模块的工作，和本轮补齐现有 PXA 接口有区别。
没有注册未实现的能力，也没有让其他板卡默认加载这些硬件驱动。

## 验证及内存

```sh
bash firmware/boards/esp-mosaico/tests/test_host.sh
bash firmware/boards/esp-mosaico/tests/test_lvgl.sh
# 激活支持 esp32s31 的 ESP-IDF 后：
tools/firmware.sh esp-mosaico build
```

本次验证结果：

- ASan/UBSan：双指交错输入、快速 DOWN/UP、逐指取消、物理接管、后到的远程取消、
  非法 ID/坐标、电池字节序、正负电流、满充/无电池、异常值、失效恢复和 tick 回绕通过。
- 真实 LVGL：两指快速点击、取消不误点击、实体接管不点击远程目标并恢复实体点击通过；
  保留之前 30 帧滚动/圆角/半透明 UI 的半高/全高缓冲逐字节一致测试。
- Surface backend 的 ASan/UBSan 回归通过，覆盖锁屏、power overlay、恢复新帧屏障等路径。
- ESP32-S31 构建和分区大小检查通过；构建输出的正常中文字体路径已核对。

相对上一轮 UI 优化后的构建，`g_hardware` 从 6280 B 变为 6304 B，
**静态 SRAM 增加 24 B**，用于本轮新增状态；`.dram0.bss`、IRAM 和静态 PSRAM
大小不变。没有新增任务栈、帧缓冲或命令队列。移除了额外的 LVGL 注入设备；
电量计首次发现时由 IDF 创建一个 I2C device 及链表节点，缺少电量计时不分配。
这两项运行时分配的净额及真实堆峰值未进行设备测量，不能只凭静态 map 判断整机峰值。
前一轮减少的 450 KiB 固定 PSRAM 绘制缓冲仍保留。

当前工作区构建产物中 Flash text/rodata 相对上一轮分别增加 6072/368 B，
新增功能没有引入大型默认缓存。固件为 3,976,752 B，应用分区剩余 217,552 B。
完整 SHA-256 和 map 数据保存在 `local/mosaico-pxa-20261015/memory.json`；
测试日志及 `firmware-verified.log` 在同一目录。

**未进行本轮真机刷写。** 驱动时序已核对并完成构建，尚未验证 Mosaico 上的
实际 SOC/充电指示、物理关机、关机保存成功率、唤醒延迟和新增采样的触摸延迟分布。
