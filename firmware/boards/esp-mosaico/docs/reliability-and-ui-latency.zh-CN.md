# ESP-Mosaico 可靠性与 UI 延迟补充

日期：2026-10-15。基于本地 UI 优化及 PXA 接入阶段继续修复；本轮没有烧录设备。
基线是 `local/mosaico-refine-20261015/before/` 的源码与 map，包含此前接入工作，
不是仓库 HEAD。没有改变画质、分辨率、刷新缓冲容量或音频 DMA 容量。

## 修改及原因

| 问题 | 处理方式 | 预期收益与证据 |
| --- | --- | --- |
| 每五秒从 UI 线程读取 ES8311 寄存器；codec 控制层单次 I2C 默认超时 100 ms | 寄存器只在初始化时读取并以 `codec_boot` 输出；周期诊断只读计数器、逻辑音量、PA 引脚及可用的音乐统计 | 去除这条周期 UI I2C 等待路径。生产音频代码在模拟 I2C 失败时连续诊断十次，寄存器读取计数不再增加 |
| 音乐统计通过无限等待获取混音器锁 | `GetMusicStats` 改为尝试立即获取；忙时返回 false，保持调用方输出不变 | UI 诊断可以跳过本次音乐统计；原生测试持有锁后读取，确认立即失败且未覆盖原快照 |
| LVGL 阻塞期间触摸队列溢出，强制释放可能点击原来按住的按钮 | 取消标记随释放样本入队，消费时调用 `lv_indev_wait_release`；标记只交付一次 | 真实 LVGL 中先按住旧按钮，再积压九次其他位置的点击，旧实现误点击，修复后通过 |
| 实体触摸接管后，迟到的远程 DOWN 再次抢占，或远程 UP 释放实体手指 | 实体触点尚未抬起时拒绝远程 DOWN，远程 UP 忽略但返回成功 | 原生及 LVGL 测试验证接管、取消和迟到命令；实体手指继续拥有输入 |
| 音频写入失败触发 DMA 恢复，与关机关闭功放并发 | 停止标记阻止后续写入/恢复，关机复用 PCM 锁等待在途操作，再关闭 PA 和 I2S | 生产代码并发测试覆盖“写入失败前停止”与“恢复已开始后停止”两个交错，停止返回后 PA 均保持关闭 |
| `device_paced` 输出停止 DMA 后立即返回，可能使 Host 输出任务空转 | 停止后的回调丢弃 PCM，按样本数保持软件等待 | 测试连续丢弃一百个 320 样本块，没有 I2S 写入，累计请求等待 2000 ms；这是虚拟时钟测试，不是真机测量 |
| Guest 未确认停止仍切断电源，可能中断保存 | 未获确认则取消物理重启/关机，恢复输入与电源菜单供重试；先清除电源操作状态，再通知 UI，保证另一个核恢复时看到正确状态 | 消除这条超时后继续切电路径；固件编译通过，实际电源和保存行为仍需设备验证 |
| I2C 超时或取消关机后绝对轮询时钟落后，输入任务连续补跑历史周期 | 落后超过一个 10 ms 周期时重新设置轮询基准 | 避免优先级 6 的输入任务补跑过期周期；正常轮询周期不变。设备调度收益尚未测量 |

周期日志不再表示实时 codec 寄存器状态。`codec_boot` 仅记录启动时寄存器，
后续排查以实际 DMA 完成计数、非零块、PA 状态及欠载统计为依据。
音乐统计仍是设备累计值，混音器忙时该行可能缺失。

Host 的 1200 ms 参数是 Guest 停止期限，同步等待还有最多 500 ms 调度余量，
不是严格的 1200 ms 整体关机时间。取消物理电源操作不会撤回已经排队的 Guest
停止请求，应用仍可能稍后退出。没有把 Host 确认等同于持久化介质绝对不会丢数据。

## 验证

在工作区根目录运行：

```sh
bash firmware/boards/esp-mosaico/tests/test_host.sh
bash firmware/boards/esp-mosaico/tests/test_lvgl.sh
# 已有的共享组件脚本也包含新增音乐统计测试：
bash firmware/components/pxa/tests/test_host.sh
# 激活支持 esp32s31 的 ESP-IDF 后：
tools/firmware.sh esp-mosaico build
```

本轮实际执行的检查：

- 板级原生 ASan/UBSan：显示管线、不可变快照、局部合成、触摸及生产音频代码通过。
  音频测试使用 IDF stub，并以两个真实主机线程构造关机与恢复竞态。
- 真实 LVGL：取消、溢出、双指、实体接管通过；30 帧滚动、半透明与圆角画面，
  全高和半高缓冲输出逐字节一致（分别 59/89 次 flush）。这是正确性验证，不是 FPS。
- 单独编译并运行共享 `pxa_audio_output_test.cc` 的 ASan/UBSan 测试通过，
  包含忙锁统计、缓存/预算回滚、音乐替换、取消、预缓冲、EOF、欠载与所有权隔离。
  本轮没有重新执行整个共享组件脚本；上方完整命令用于复现和扩大回归范围。
- ESP32-S31 板级构建、codec 内存分配审计及应用分区大小检查通过。
  二进制保留 `/pxa/system/fonts/noto_sans_cjk_common.ttf`，不含临时维护字体路径。

输入结构主机探针修复前后均为：`Sample=24 B`、单队列 `432 B`、
`EspMosaicoInput=888 B`。取消标记使用样本原有对齐空间，并移除独立取消位图。
同一探针中，实体手指按住时远程 DOWN 从错误接受变为拒绝。

## 内存与固件

以下是同一工作区配置、相邻构建的静态 map 对比：

| 区域 | 修改前 | 修改后 | 变化 |
| --- | ---: | ---: | ---: |
| `.dram0.data` | 39,196 B | 39,196 B | 0 |
| `.dram0.bss` | 31,320 B | 31,320 B | 0 |
| `.iram0.text` | 105,806 B | 105,806 B | 0 |
| `.ext_ram.bss` | 36,016 B | 36,016 B | 0 |
| `g_hardware`（已包含在 data 内） | 6,304 B | 6,304 B | 0 |
| `.flash.text` | 3,040,628 B | 3,041,120 B | +492 B |
| `.flash.rodata` | 790,624 B | 790,656 B | +32 B |

没有新增生产堆分配、任务、队列或帧缓冲，音频停止标记利用对象对齐空间。
此前减少的 450 KiB PSRAM 绘制缓冲仍保留。静态 map 不能衡量运行时任务栈高水位、
Guest 线性内存及堆真实峰值，本轮没有设备运行数据，不能据此声称整机峰值已测定。

最终固件 3,977,280 B，4 MiB 应用分区剩余 217,024 B。日志、原始失败复现、
结构大小探针、SHA-256 和 map 摘要位于 `local/mosaico-refine-20261015/`；
最终构建日志为 `firmware-final-verified.log`，内存数据为 `memory.json`。

## 仍需真机验证

本轮收益来自移除可证明的等待/补跑路径及修复误操作，尚无新的真机 FPS、
P95/P99 触摸延迟、声音实测延迟或堆峰值数据。待验证项包括：正常与故障 I2C 下
滚动时延、实体/远程输入连续接管、Guest 保存超时恢复，以及实际重启和 SAM8108
关机。启动阶段诊断仍会访问 codec I2C；本轮处理的是周期 UI 阻塞。

尚未接入的 IMU、磁力计、震动、录音、NAND 和 light sleep 仍受驱动或服务协议
缺失限制，详见 [PXA 接入核对](pxa-integration-audit.zh-CN.md)，没有注册空实现。
