# ESP-Mosaico 设置页与下拉面板真机测量

设备：ESP32-S31 rev0.0，MAC `1c:29:04:d0:ad:04`，480×480、305 DPI、
CO5300 48 MHz QSPI，`/dev/ttyACM2`，2,000,000 baud。日期：2026-10-16。
本报告接续 [UI 优化记录](ui-performance-optimization.zh-CN.md)。

## 测量口径与已确认结果

旧固件为 `586e1db-d`。设置首页连续滚动两轮的实际完成帧计数约为
**17.57、17.97 FPS**；下拉面板展开/收起约为 **15.89、15.53 FPS**。
设置页采样中绘制为 51.7–58.2 ms，快照复制约 8 ms，传屏为 17.7–21.5 ms。
这些是诊断时刻的最近一次刷新，不能相加当作同一帧耗时，也不是阶段 P95。
一帧传输与下一帧绘制可以重叠；设置页首先受绘制侧限制。

旧 Mosaico 没有调用 `pxa_esp_surface_note_display_frame_presented`，其
`PERF START display` 返回零计数，不代表屏幕没有刷新。跨旧固件比较使用截图
元数据中的完成帧编号差，除以首个注入 DOWN 确认至最后一帧完成的设备时间。
新固件同时记录这组数据及接通后的完整 PERF 显示窗口。两种窗口边界稍有不同，
不混在同一列计算收益。

| 固件与场景 | 完成帧计数法，第 1 / 2 轮 | 完整 PERF 显示窗口，第 1 / 2 轮 |
| --- | --- | --- |
| 原版，设置首页 | 17.57 / 17.97 FPS | 未接通，不能使用零值 |
| 保留画面、面板字节序、单绘制线程，设置首页 | 24.13 / 24.41 FPS | 23.99 / 24.28 FPS |
| 原生 RGB565/PPA、双绘制线程，设置首页（预热后） | 24.00 / 23.98 FPS | 23.86 / 23.82 FPS |
| **最终：原生 RGB565/PPA、单绘制线程，设置首页（预热后）** | **25.62 / 25.71 FPS** | **25.38 / 25.57 FPS** |

单线程面板字节序行是 `single-settings-root-final`，首尾截图均确认在设置首页。
相同计数法的均值较旧版提升约 **36.6%**。该版本帧间隔中位数
35.31 / 34.87 ms，P95 为 52.55 / 52.32 ms，最长 69.64 / 67.36 ms；
该中间版本不能称为稳定 30 FPS。用户也报告设置页最高约 28 FPS、体验变流畅；
峰值反馈与完整往返手势均值分别记录。

### 排除错误负载

必须核对截图，而非只看文件名或提交 FPS：

- `candidate-settings-final` 实际在“声音与显示”子页，不能与设置首页比较。
- `retained-two-shade`、`retained-single-settings`、`single-settings-root`、
  `single-settings-verified` 等试跑受到起始下拉面板状态影响。
- 一次 `candidate-shade` 误启动浏览器，有 Guest 运行时的 CPU/内存不能
  与纯系统 UI 作为相同工作负载比较。
- `INPUT KEY HOME` 本身不会关闭已经打开的下拉覆盖层；左上角所谓“唤醒点击”
  又可能打开下拉面板。脚本现先 BACK 关闭覆盖层，再 HOME，等转场结束后打开设置。

以上数据仍保留供追溯，但不用于收益表，也不能据此断言单/双绘制线程的快慢。
下拉手势每次释放后停顿 150 ms，其流程均值也不能当作持续动画最高 FPS。

## 保留 UI 画面，省去中间合并

原路径：两块 240 行 LVGL 临时缓冲 → 完整 producer → 不可变 scanout → DMA。
新路径：一块 480 行 LVGL 保留缓冲 → 不可变 scanout → DMA。LVGL DIRECT
只重绘脏区域，提交前复制一次，不再逐块合并到另一个完整画面。

绘制容量同为 460,800 B。游戏 producer、scanout、两块 16 行 SRAM DMA 缓冲、
单帧背压、TE 规划及回退均保留；没有新增帧缓冲或队列。
游戏直出仍交换 producer/scanout；返回 UI 时在 `RENDER_START` 恢复保留画面，
之后才绘制新补丁，避免恢复旧帧时覆盖新控件。
单绘制线程候选另外减少约 32 KiB SRAM 任务栈。

## 原生 RGB565 与 PPA 快照候选

LVGL 改为原生 RGB565，减少每个文字和半透明像素的字节序处理。
最终提交复用已有 PPA SRM 客户端，对宽区域展开后的完整行进行 1x 复制/字节交换；
小于 4096 像素、窄区域、加速不可用或失败时使用成对 CPU 转换。
PPA 驱动会失效完整输出行的缓存，窄区域可能丢弃区域外的 CPU 脏像素，
因此不将窄矩形交给 SRM。480 像素 RGB565 每行 960 B，按 S31 的 64 B 缓存行对齐。
游戏直出仍使用面板字节序，返回 UI 时先恢复并转换保留画面。
未增加客户端、帧缓冲、任务或队列容量。该候选恢复原来的两个软件绘制线程，
不启用每个小图元都进行缓存同步的 LVGL PPA 绘制后端。

候选镜像 3,981,360 B，SHA-256：
`70e851189ef0fe0e9ec8c0000b12925e665e619dd6c40ef3dc5256240c8ba6be`。
同工作区相邻构建的 SRAM/静态 PSRAM/IRAM 不变，Flash text 增加 1,876 B。
这份构建基线包含后续 AOT 改动，不等于旧设备 `586e1db-d` 的完整镜像。
双线程候选已经在设备写入并通过散列校验。设置首页三轮完整窗口为
22.04 / 23.86 / 23.82 FPS；第一轮单独记录为首次运行，表中列后两轮。
其最近快照采样约 4.68–4.78 ms，绘制整体仍约 42–44 ms。
快照更快没有自动变成更高显示帧率；该组合未超过已验证的单线程面板字节序版本。
下拉流程两轮为 11.81 / 19.11 FPS（同完成帧计数法 12.02 / 19.22 FPS），
首轮与后续有明显差异，不能只挑后者宣称提高。首轮成本的具体来源尚待进一步隔离。

真机设置首页截图 `(0,64)–(480,448)` 区域与旧固件共 184,320 个 RGB 像素全部相同。
排除时钟、状态栏和 FPS 后，这个静态画面对照确认没有颜色或布局取舍；
不能替代对实物屏幕撕裂的动态观察。

最终采用单线程原生 RGB565/PPA，已实际写入设备并校验：

- 设置首页首次测量 23.87 FPS，后两轮 25.38 / 25.57 FPS。
  同完成帧计数法的热身后均值相对旧版提高约 **44.4%**，
  相对面板字节序单线程版本提高约 5.7%。不把冷、热样本混作同一均值。
- 设置首页热身后帧间隔中位数 34.42 / 34.26 ms，P95 为 51.76 / 51.42 ms，
  最长 84.41 / 67.21 ms。首次窗口最长 236.54 ms，仍未达到稳定 30 FPS。
  活跃滚动诊断采样 `render_us` 约 30.62–38.02 ms、快照约 4.7–5.4 ms；
  这些阶段最近值不能与窗口分位数混用。
- 下拉完整流程首次 **11.81 FPS**、后两轮 **19.47 / 19.52 FPS**；
  同完成帧计数法分别为 12.02、19.42 / 19.53 FPS。
  旧版已使用过下拉面板，缺少对应冷启动样本，不能据此判断首次打开的回退幅度。
  新版首次流程确有一次 **1.63 秒完成帧间隔**，超过预设的 150 ms 手势停顿，
  本轮未定位来源。正常重启后改用主指针 0 复测，首次为 11.86 FPS，
  最长完成帧间隔 1.10 秒，后两轮 19.51 / 19.27 FPS，
  确认不能只归因于副指针测试；数据为 `native-single-primary-shade`。
  这只是完成帧间隔，尚未证明整个间隔都在绘制。后续流程也有释放/动画形成的约 0.5 秒间隔，
  完整流程 FPS 不能作为持续拖动峰值。不能用热身后的 19.5 FPS 掩盖首轮卡顿。
- 原生与旧版设置页的 184,320 像素区域保持一致，游戏退出后再进入设置也完全一致。
  通过真实主指针点击重新打开设置，验证排队指针状态修复实际生效。

正常重启后主指针设置首页两轮为 23.75 / 25.24 FPS（首次 / 后续），
同完成帧计数法 23.89 / 25.31 FPS，见 `native-single-primary-settings`；
支持主指针修复和预热后收益，但不将不同指针的样本混算提升比例。

最终镜像 `native-single.bin`，3,981,104 B，SHA-256：
`1103764aee9046ad847ee43b101ed480e7be3a9c951cbbae180fd9fd96731eaa`。
数据见 `native-single-settings`、`native-single-shade`。

### 游戏与生命周期复测

`native-single-game` 使用现有 Jump Jump 3D 0.1.5，重复两次启动、蓄力、释放、退出。
主指针蓄力截图出现人物下压和粒子，确认确实向 Guest 送达操作。
完整显示窗口为 **27.21 / 26.87 FPS**，帧间隔中位数 33.98 / 33.89 ms，
P95 为 36.29 / 36.22 ms。测试中可能失败和重新开始，属于交互冒烟，
没有旧固件相同游戏窗口，不能据此宣称游戏提升比例或与其他语言版本比较。
最初使用副指针的试跑未确认 Guest 接收，移至 `native-single-game-pointer1*`，
不作为游戏交互验证证据。

`PERF INPUT` 的软件采样至显示完成均值约 103.6 / 99.6 ms、
P95 约 169.9 / 152.6 ms，仍不算低；采样计数包含持续按住期间的输入更新，
不是一次物理触摸按下的独立延迟，也没有测量屏幕发光响应。
音频诊断确认非零 PCM、无写入错误、无恢复和音乐欠载；不等同于声学延迟测试。

游戏直出、返回系统 UI、重复启动和关闭后的截图正确。
两个应用均保留且 inactive，存储仍为 used=8,704,000 B、free=3,813,376 B，
音量 75%、亮度配置 100%、深色主题保持。SPI 错误与 TE 超时为零；
后续游戏测试累计出现两次 `scan_overruns`，不能声称所有帧都满足扫描期限。
触摸控制器约 8% 的既有无效响应仍可见，本轮未修复电气/驱动层原因。
自动化注入不能代替实体触摸的全链路时延验证。

## 内存与正确性

最终固件与本工作区构建基线的 `.dram0.data`、`.dram0.bss`、IRAM、静态 PSRAM
均不变，Flash text +1,688 B、rodata −80 B；未开启 PSRAM XIP，
没有因代码增加复制更多指令到 PSRAM。单线程相比原来的双线程约省 32 KiB SRAM。
UI/producer/scanout 总容量仍是 3 × 460,800 B，DMA 仍是 2 × 16 × 480 × 2 B，
提交仍是一项在途快照。这些显示改动不调整深度缓冲、Guest 线性内存或命令队列。

| 预热 2 | 115,139 / 114,915 B | 13,932,816 / 13,923,268 B |

本次最低 95,663 / 95,851 B，临时占用 224 / 36 B。
PSRAM 起始空闲 13,897,280 / 13,896,640 B，

旧版对应窗口 SRAM 起始空闲 63,043 B，临时占用 224 B；
PSRAM 临时占用 10,636 / 9,664 B。
字体、图片及退出应用后的缓存状态不同，不能把重启前后所有空闲堆差额都归因于渲染。
单/双线程的配置栈差与这些动态缓存差额分开解释。

真实 LVGL 的 30 帧滚动、圆角、半透明和四次游戏直出后 UI 恢复，
原生与旧交换字节序路径逐字节一致。生产合成器以 ASan/UBSan 验证
RGB565 1x/2x/4x、预乘 ARGB、独立步长、受保护 UI、重叠 alpha 平面、
未对齐 CPU 转换与 PPA 失败回退。

LVGL 手势 `set_data` 会按当前触点集合改写 `data->state`，可能覆盖排队的旧
DOWN/UP，使远程主指针点击失效。现在保留队列状态，只附加手势元数据。
开启真实识别器后，原实现双指点击断言失败，修复通过；取消和实体触摸接管也通过。
LCD 成功完成后才计 display PERF，不把 flush 分块当作完整帧。

## 复现

保持本设备的三个图标布局（设置位于第一项），先停止前台 Guest，再运行：

```sh
python3 firmware/boards/esp-mosaico/tests/measure_device.py settings \
  --page settings --port /dev/ttyACM2 --baud 2000000 \
  --output local/mosaico-ui-measurement
python3 firmware/boards/esp-mosaico/tests/measure_device.py shade \
  --page shade --port /dev/ttyACM2 --baud 2000000 \
  --output local/mosaico-ui-measurement
bash firmware/boards/esp-mosaico/tests/test_host.sh
bash firmware/boards/esp-mosaico/tests/test_lvgl.sh --gestures
```

脚本先关闭覆盖层、返回主页并等待，再按场景打开设置或保留主页；仍需检查
`launcher`、`start` 和每轮前后截图。设置页为按住后十次上下交替移动，
每段 650 ms、65 步；下拉为八次展开/收起。测量期间不要操作实体屏幕。
固定分辨率、DPI、字体、主题与坐标，音量保持 75%、亮度 100%。
脚本默认主指针 0；跨旧固件的收益表均使用副指针 1，复现这些行请加
`--pointer-id 1`，旧固件主指针受队列状态覆盖问题影响。JSON 显式记录指针 ID；
早期未带该字段的记录使用 1。
截图在计时窗口之外，期间临时开启结构化日志，防止原始串口日志切断 DATA。
普通测量窗口读原始日志，避免仅四条记录的固件 LOGSUB 队列丢掉诊断尾部。
日志可能夹带订阅队列的旧诊断，应按设备时间筛选，不能把历史最近值当作当前阶段采样。
`MEMORY START/STOP` 使用本次窗口最低空闲，不能用历史 `min_free` 代替本次峰值。

原始日志、固件、构建源码、截图和 JSON 保存在 `local/mosaico-device-20261016/`。
旧版对应 `baseline-*-scanout`；最终样本为 `native-single-settings`、
`native-single-shade`、`native-single-game`，`single-settings-root-final` 是上一中间版本。

## 下载链路

ROM rev0 下载态对连接开关敏感；不在写入前另开 `chip-id` 探测。
最初 RAM stub 在 USB-OTG 传输约 4.5% 时掉线，已由 ROM 完整写入恢复，
使用 `--no-stub --no-compress` 校验通过，约 85 秒。
只写 `0x10000` 应用分区，未改分区表、NVS 或应用数据。
后续两次候选更新分别约 130 / 115 秒，均通过散列校验。ROM 枚举后 udev
权限短暂未就绪时首次打开失败，重试成功；不能把它当成传输中断。
UART 上的 stub 成功经验不能直接外推到这条 USB-OTG 链路。

后续将快照转换移到传屏任务的实现与对照，见
[UI 并行流水线记录](ui-parallel-pipeline-20261016.zh-CN.md)。
